# 全场景车牌优先自适应曝光：方案设计

> 配套文档：[research.md](research.md)（技术调研/引用）、[forensics.md](forensics.md)（现有素材取证与可读阈值）
> 目标设备：HUAWEI P30（ELE-AL00 / Android 10 / API 29 / EMUI），第三方 Camera2 App
> 代码基线：icu.wwj.drive v1.2.0

---

## 1. 问题与实测证据

固定 EV 无法覆盖全场景，取证结果给出了量化原因：

| 现象 | 实测证据（forensics.md） |
|---|---|
| 夜间整体压暗但高光照样削顶 | 本项目夜间 180s 水印恒为 `1/50 ISO 115`；全帧均值中位 30.9（旧 DVR 同场景 67.5），20:16:58 有 50.8% 像素 <30 灰阶，而高光 p99 与旧 DVR 基本相同（185 vs 177） |
| 夜间"看得见、读不出" | 蓝牌 `沪B·AT158` 路灯下字符-底色差 59、对比度 73 → 可读；被前车尾灯红光浸染的 `豫Q·052M1` 字符-底色差只剩 19、对比度 39 → 不可读 |
| 单通道削顶 | 蓝牌 B 通道 23.3% >240、绿牌 G 12.3%、尾灯 R 8.7% |
| 白天用夜间参数的后果 | 夜间正确曝光约 EV100≈5.4；正午 f/1.8 正确曝光约 1/8000s ISO100，相差约 **7.3 档**；固定 -1.5EV 会让白天车牌欠曝 |
| 运动模糊 | 曝光期车牌相对位移 ≤ 字符笔画宽（20mm）才可读：1/50s 只允许相对速度 ≤3.6km/h；1/200s ≤14km/h；1/500s ≤36km/h。同速跟车 1/50s 仍锐利，横穿出租车 1/50s 拖影 40–70px |
| 分辨率 | 1080p 10m 处 44cm 车牌约 63px，低于可读门槛（本集最窄可读 88px，GA/T 833 要求 >100px）；4K 理论 127px，但本机 4K+GL 组合不稳定 |

**可读性判据（forensics 经验值，4K 原生）**：车牌宽 ≥88px（建议 ≥120px）；字符-底色差 ≥36 灰阶（<25 不可读）；对比度 p90-p10 ≥45；任一通道过曝 ≤10%（中小牌）或 ≤25%（≥200px 大牌）；锐度 Tenengrad 仅辅助。**整帧亮度/背景亮度不能作为判据。**

## 2. 设备约束（P30 实机确认）

| 项 | 实测/官方结论 | 对方案的影响 |
|---|---|---|
| AE 补偿 | `CONTROL_AE_COMPENSATION_RANGE=[-4,4]`、`STEP=1/2` → ±2EV/0.5EV | 纯 EV 调节粒度粗，无法精细保护车牌 |
| AE 区域 | `CONTROL_MAX_REGIONS_AE=1`；API 只定义"加权测光"，厂商实现差异大 | 不用系统 AE regions 作为主方案 |
| 手动曝光 | `AE_MODE_OFF` + `SENSOR_EXPOSURE_TIME`/`SENSOR_SENSITIVITY` 可用；ISO 50–6400；曝光 10µs–1s | 可自建逐帧闭环 |
| 硬件级别 | `INFO_SUPPORTED_HARDWARE_LEVEL=0`（LEGACY）、无 `MANUAL_SENSOR` 能力声明（但手动曝光实际生效） | 3A 行为边界不确定，必须兜底 |
| HDR | 无标准 HDR 场景模式；HDR 视频需 API 33 + 10-bit；CameraX/Camera2 extensions 不覆盖视频 | 不能用 HDR/WDR 当主路径 |
| 50Hz | 手动 AE 下 antibanding 不生效，曝光必须是 10ms 整数倍 | 夜间快门只能 10/20/30ms（1/100、1/50、1/30）；想 1/200 只能接受条纹 |
| 分辨率 | 1080p 10m 车牌 63px；4K 本机不稳定 | **分辨率/变焦比曝光更决定车牌可读性** |

## 3. 方案总览

按"投入产出比"分层，L0/L1 是默认交付，L2 是实验增强：

```
L0  分辨率/变焦：1080p + 2× 数字变焦（或 2.1× 长焦）→ 车牌 ≥88–120px
L1  自适应 EV（默认）：系统 AE + 曝光归一化场景亮度 + 高光裁剪反馈，0.5EV 步进
L2  车牌优先闭环（实验）：960×540 YUV 测光 → 结构化高光块/车牌 ROI → 手动曝光+ISO
L3  遥测与验收：DashcamAE/DashcamAEV 日志 + ffprobe/ROI 量化脚本
```

### 3.1 L0：先把车牌拍够大（前提）

1. 设置建议默认 1080p + 2× 数字变焦（`Settings.ZOOM_FACTORS[2]`），或改用 2.1× 长焦（需验证视频能力）；
2. 4K 只有在确认 HAL 稳定时使用；
3. 不改变现有默认视场，作为"车牌模式"预设由用户选择（避免牺牲行车记录视野）。

> 没有 88px 的车牌宽度，曝光再好也读不出字；这是本方案的第一优先级。

### 3.2 L1：自适应 EV（默认，已实现）

动机：EV 补偿粒度粗，但足以解决"夜间要 -1.5、白天要 0"的**场景级**问题；系统 AE 负责快门/ISO，稳定、风险低。

控制量：`CONTROL_AE_EXPOSURE_COMPENSATION`（0.5EV 步进），每 800ms 最多变一档。

场景分类（曝光归一化，避免"改曝光→亮度变→误分类"的自激）：
```
norm = mean(道路 ROI) × (16.67ms / 当前曝光) × (800 / 当前 ISO)
NIGHT: norm < 80；DUSK/TUNNEL: 80–400；DAY: > 400
基准 EV：NIGHT -1.5；DUSK -1.0；DAY 0.0
高光反馈：ROI p99≥252 或裁剪>6% → 再降 0.5EV；裁剪>15% → -2.0EV
```
实测（P30 夜间室内）：`scene=3 norm=14 mean=50 p99=56 ev=-1.5`，稳定不 oscillate；白天把 EV 拉回 0，解决 -1.5 导致车牌发黑的问题。

### 3.3 L2：车牌优先闭环（实验，已实现骨架）

用现有 960×540 YUV 测光流（已验证可与 1080p 录制共存）：

1. **车牌代理**：把下方道路 ROI 切成 16×16 像素块，选出"高亮度（p90≥150/170）+ 高内部对比（std≥14/18）+ 非均匀过曝灯芯"的块，取这些块的 p90 作为"车牌代理亮度"；没有就退回路面高光加权。
2. **目标**：夜间 198、黄昏 205、白天 218（p90，8bit）；过曝硬保护。
3. **快门**：
   - 夜间/黄昏：只允许 50Hz 安全档 **10/20/30ms**（1/100、1/50、1/30）；
   - 白天：0.5–10ms 档；
   - 上限按相对速度：`vEff = max(v,15) + 0.5v` → 1/100→1/250→1/500→1/1000。
4. **过曝处理**：先缩短曝光（传感器满阱饱和后降 ISO 不一定有效），快门到下限再降 ISO。
5. **欠曝处理**：先加快门到运动上限，再升 ISO（上限 6400）。
6. **稳定性**：150ms 控制周期、0.9EV 限速、死区 0.1EV、符号翻转阻尼、场景滞回 1.5s、启动 seed（夜间 1/100 ISO2000）。
7. **兜底**：测光流创建失败 → 自动回退系统 AE + 固定 EV，不会停在 seed 曝光。

离线仿真结果（合成夜景/日景/黄昏，30–50km/h）：夜间收敛到 p90=198、白天 205、黄昏 190，无振荡；真实设备夜间日志稳定在 10ms/ISO6400（暗场景上限）。

### 3.4 L3：遥测与验收

日志（已实现）：
- `DashcamAEV`：scene / norm / mean / p50 / p99 / clip / 实际曝光 / ISO / EV；
- `DashcamAE`：scene / blocks / plateP90 / clip / roadP90 / 目标 / note。

验收脚本（建议）：
1. 抽帧 → 车牌 ROI（forensics 的半自动颜色掩膜法）；
2. 量化：宽度、p10/p50/p90、单通道过曝、对比度、字符-底色差、Tenengrad、边缘宽度；
3. 判定：宽≥88px、字符-底色差≥36、对比度≥45、过曝≤10%/25%（组合判据）；
4. 场景覆盖：正午、多云、黄昏、夜间路灯、夜间车灯直射、隧道/桥下、横穿/对向。

## 4. 为什么不选其他路线

| 方案 | 结论 | 原因 |
|---|---|---|
| 固定 EV / 分段 EV 表 | 不满足 | 0.5EV 粒度、无法应对车灯直射与隧道过渡 |
| 系统 AE regions | 不采用 | API 不保证高光优先，厂商差异大（Note 5 忽略），P30 只有 1 个区域 |
| HDR/WDR | 不可用 | API 29 无 HDR 视频；第三方拿不到厂商 HDR；10-bit 需 API 33 |
| 多帧曝光融合 | 不现实 | 30fps 下需要双快门/双增益，P30 HAL 不开放；帧间运动配准成本高 |
| 后期色调映射 | 只能补救 | 传感器已削顶的信息无法恢复；只适合做轻微高光滚降 |
| 语义车牌检测（YOLO 等） | 暂不主用 | 960×540 下 10m 车牌仅 ~31px；低照度误检高；模型/运行时体积与离线构建冲突 |
| 纯 ROI 高光测光（无检测） | 部分有效 | 车灯/招牌会拉偏曝光，只能做 L1 兜底 |

## 5. 当前实现状态

| 能力 | 状态 |
|---|---|
| 自适应 EV（默认模式 2） | ✅ 已实现，P30 夜间实测稳定（scene=NIGHT、EV=-1.5、无振荡） |
| 车牌优先闭环（模式 3，实验） | ✅ 骨架已实现：960×540 测光、代理块、50Hz 档位、运动上限、过曝先缩曝光、seed、兜底；夜间设备日志稳定 |
| 车牌像素估算 | ✅ 设置页实时显示 10m/20m 车牌像素与所需变焦（≥88px 门槛） |
| 分辨率/变焦预设 | ⏳ 设置里已有 2×/3× 与长焦选项，尚未做"车牌模式"一键预设 |
| 真实道路验证 | ⏳ 需要用户行驶录制（夜间路灯/车灯/白天/隧道/横穿）；当前只有室内/离线验证 |
| 车牌检测（语义） | ⏳ 未进入主路径；代理块只能覆盖近距/大目标 |

### 已知限制

1. 夜间 50Hz 约束把快门限制在 ≤1/100；横穿/对向车牌的拖影无法完全消除，除非接受条纹或上 HDR（本机不可用）。
2. 960×540 测光下 10m 车牌约 31px，代理块只能覆盖近距目标；超过 ~15m 的车牌依赖 L0 变焦或 4K。
3. 车牌代理块会被夜间招牌/车灯干扰（模拟中车灯块可使 L2 卡在最小曝光）；L2 仍是实验模式，默认用 L1。
4. 4K 在本机 4K+GL 组合不稳定，分辨率提升需先解决 HAL 问题。
5. 隧道素材缺失，隧道过渡策略（-1EV + 快速滞回）尚未实测。

## 6. 下一步（按优先级）

1. **实车验证 L1**：夜/日/隧道/车灯直射各录 2–3 分钟，按 §3.4 量化；根据 `DashcamAEV` 日志调 norm 阈值。
2. **加"车牌模式"预设**：1080p + 2× 变焦 + L1（或 L2），一键切换；验证 10m 车牌 ≥88px。
3. **L2 代理块升级**：用 1920×1080 测光流（若 HAL 支持）或 2× 变焦后的 960 流，提高 10–20m 车牌的结构可见性。
4. **隧道过渡**：补隧道素材，调 EV 回落速度与滞回。
5. 如果后续要上 HDR：换 API 33+ 设备/机型，走 `DYNAMIC_RANGE_PROFILES`，而不是在 P30 上硬做。
