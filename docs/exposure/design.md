# 全场景车牌优先自适应曝光：方案设计

> 配套：[research.md](research.md)（技术调研与引用）、[forensics.md](forensics.md)（素材取证与可读阈值）、
> [validation.md](validation.md)（离线/实验室/路测协议）
> 目标设备：HUAWEI P30（ELE-AL00 / Android 10 / API 29 / EMUI），第三方 Camera2 App

---

## 1. 问题与证据

| 现象 | 实测证据 |
|---|---|
| 夜间压暗 + 高光削顶 | 本项目 App 夜间水印恒为 `1/50 ISO 115`；全帧均值中位 30.9（旧 DVR 自动 AE 同场景 67.5），50.8% 像素 <30 灰阶，而高光 p99 基本相同（185 vs 177）——动态范围被压扁 |
| 夜间"看得见、读不出" | 路灯下可读蓝牌字符-底色差 59、对比度 73；被前车尾灯红光浸染的样本字符-底色差只剩 19、对比度 39 |
| 白天用夜间参数的后果 | 夜间正确曝光约 EV100≈5.4，正午 f/1.8 约需 1/8000s ISO100，相差约 7.3 档 |
| 运动模糊 | 曝光期车牌相对位移 ≤ 字符笔画宽（20mm）才可读：1/50s 只允许相对速度 ≤3.6km/h；1/200s ≤14km/h；1/500s ≤36km/h |
| 分辨率 | 1080p 在 10m 处 44cm 车牌约 63px，低于可读门槛（本集最窄可读 88px，GA/T 833 要求 >100px）；4K 理论 127px，但本机 4K+GL 组合不稳定 |

**可读性判据（forensics 经验值，4K 原生）**：车牌宽 ≥88px（建议 ≥120px）；字符-底色差 ≥36 灰阶（<25 不可读）；
对比度 p90-p10 ≥45；任一通道过曝 ≤10%（中小牌）或 ≤25%（≥200px 大牌）；锐度仅辅助。
**整帧亮度/背景亮度不能作为判据。**

## 2. 设备约束（P30 实机确认）

| 约束 | 结论 | 对方案的影响 |
|---|---|---|
| AE 补偿 | 范围 ±2EV、步进 0.5EV | 调节粒度粗，无法精细保护车牌 |
| AE 区域 | 最多 1 个；API 只定义"加权测光"，厂商实现差异大 | 不用系统 AE regions 作主方案 |
| 手动曝光/硬件级别 | `AE_MODE_OFF` + 曝光时间/ISO 可用（ISO 50–6400）；硬件级别 LEGACY、无 `MANUAL_SENSOR` 声明，但手动曝光实际生效 | 可自建逐帧闭环，但 3A 边界不确定，必须有兜底 |
| HDR | 无标准 HDR 视频入口；HDR 视频需 API 33 + 10-bit；extensions 不覆盖视频 | 不能用 HDR/WDR 当主路径 |
| 50Hz | 手动 AE 下 antibanding 不生效，曝光必须是 10ms 整数倍 | 夜间快门只能 10/20/30ms；想 1/200 只能接受条纹 |
| 分辨率 | 1080p 10m 车牌 63px；4K 本机不稳定 | **分辨率/变焦比曝光更决定可读性** |

## 3. 方案分层

按投入产出比分层，L0/L1 是默认交付，L2 是实验增强：

- **L0 分辨率/变焦（前提）**：先把车牌拍够大。默认 1080p；车牌优先场景用 2× 数字变焦或 2.1× 长焦，
  目标 10m 处车牌 ≥88–120px；4K 只在确认 HAL 稳定时使用。变焦/长焦作为"车牌模式"由用户选择，
  不牺牲默认行车视野——像素不够，曝光再好也读不出。
- **L1 自适应 EV（默认）**：系统 AE 负责快门/ISO，App 只用曝光归一化的场景亮度区分白天/黄昏/夜间，
  并在高光裁剪时继续压曝光，自动在 0 / -1 / -1.5EV 间调整；稳定、风险低，夜间实测 `scene=NIGHT EV=-1.5` 无振荡。
- **L2 车牌优先闭环（实验）**：960×540 测光流上找车牌代理块（高亮 + 内部对比 + 排除过曝灯芯），
  按代理块亮度手动控制曝光/ISO；夜间只用 50Hz 安全快门档，按车速限制最长曝光，过曝先缩短曝光，
  测光流失败回退系统 AE。只覆盖近距/大目标，默认仍用 L1。
- **L3 遥测与验收**：逐秒 AE 遥测 CSV、自动 EV 包围、抽帧/分析脚本，按组合判据验收。

## 4. 为什么不选其他路线

| 方案 | 结论 | 原因 |
|---|---|---|
| 固定 EV / 分段 EV 表 | 不满足 | 0.5EV 粒度，无法应对车灯直射与隧道过渡 |
| 系统 AE regions | 不采用 | 不保证高光优先，厂商差异大，P30 只有 1 个区域 |
| HDR/WDR | 不可用 | API 29 无 HDR 视频；第三方拿不到厂商 HDR；10-bit 需 API 33 |
| 多帧曝光融合 | 不现实 | 30fps 下需要双快门/双增益，P30 HAL 不开放；帧间配准成本高 |
| 后期色调映射 | 只能补救 | 传感器已削顶的信息无法恢复，只适合轻微高光滚降 |
| 语义车牌检测（YOLO 等） | 暂不主用 | 960×540 下 10m 车牌仅约 31px；低照度误检高；模型体积与离线构建冲突 |

## 5. 状态与限制

| 能力 | 状态 |
|---|---|
| 自适应 EV（默认模式 2） | ✅ 已实现，P30 夜间实测稳定 |
| 车牌优先闭环（模式 3，实验） | ✅ 骨架已实现；夜间设备日志稳定，默认不启用 |
| 车牌像素估算 | ✅ 设置页实时显示 10m/20m 车牌像素与所需变焦（≥88px 门槛） |
| 路测数据采集 | ✅ 逐秒 CSV 遥测 + 自动 EV 包围 + 抽帧/分析脚本 + 可打印靶标（v1.3.0） |
| 真实道路验证 | ✅ 2026-11-27 早/晚两段路测（4K）；白天/黄昏/夜间近距车牌可读；已据此修场景抖动。仍需隧道/横穿素材 |

已知限制：
1. 夜间 50Hz 约束把快门限制在 ≤1/100；横穿/对向车牌拖影无法完全消除（HDR 本机不可用）。
2. 960×540 测光下 10m 车牌约 31px，代理块只覆盖近距目标；更远车牌依赖 L0 变焦或更高分辨率。
3. 车牌代理块会被夜间招牌/车灯干扰（仿真中车灯块可使 L2 卡在最小曝光）；默认用 L1。
4. 4K 在本次路测中可用，但早期组合仍可能不稳定；隧道/横穿素材缺失，过渡与运动策略尚未实测。

## 6. 下一步

1. **补实车回归**：按 [validation.md](validation.md) 重点录隧道、横穿/对向、车灯直射；用 CSV 判断夜间是否需要更亮的 EV 偏置。
2. **加"车牌模式"预设**：1080p + 2× 变焦 + L1（或 L2）一键切换，验证 10m 车牌 ≥88px。
3. **L2 测光升级**：提高测光流分辨率或结合变焦，改善 10–20m 车牌的结构可见性；同时补隧道素材。
4. HDR 换 API 33+ 设备再评估。
