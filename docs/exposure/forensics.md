# 车牌曝光失败模式取证与量化（v1）

> 任务：用现有行车素材对「车牌曝光」做失败模式取证与量化，为「车牌优先自适应曝光」提供依据。
> 取证日期：2026-11-26。所有数字均可按 §10 的命令复现；ROI 坐标以各素材的 **原生分辨率** 为准（4K 素材即 3840 宽，4 路拼接也是 3840 宽）。

> **历史材料**：文中"本项目 App 固定 `1/50 ISO 115`"是 v1.2.0 之前的实测状态，自 v1.2.0 起默认改为自适应 EV。
> 以下测量值、失败模式与阈值保持原样、不回填；实现与当前参数以代码为准，现行方案见 [design.md](design.md)。

---

## 0. 结论摘要（先看这里）

1. **夜间为什么翻车（实测证据）**：本项目 App 夜间 180 s 录制全程水印为 **`1/50 ISO 115` 固定不变**（4 个时间点采样，见 [watermark 证据](crops/night_app_watermark_1-50_ISO115.jpg)）。这组参数在夜间的效果是：全帧平均亮度中位仅 **30.9**（12.2–106.2），而旧 DVR 自动 AE 素材同场景为 **67.5**（49.6–75.6）——**暗部被压低 2.2 倍，高光 p99 却几乎相同（185 vs 177）**，即动态范围被压扁：20:16:58 帧有 **50.8% 的像素 <30 灰阶**（旧 DVR 夜间素材 15.9%，白天素材仅 0.4–3.2%），暗处几乎无信息、亮处照样削顶。实测蓝牌 ROI 蓝色通道 **23.3% >240**、绿牌绿色通道 **12.3% >240**、尾灯红色通道 **8.7% >240**。
2. **夜间车灯/尾灯是"最后一击"**：旧 DVR 在路灯下拍的蓝牌（沪B·AT158）字符-底色亮度差 **59 灰阶**、对比度 p90-p10 **73** → 清晰可读；而 App 夜间被前车尾灯红光浸没的 `豫Q·052M1`，字符-底色差跌到 **19（20:16:58）/ 无法分离（20:16:55）**、对比度只剩 **39 / 28** → 目视勉强到不可读（[可读样本](crops/night_app_00m03s_ahead_plate.png) vs [失败样本](crops/night_app_01m30s_yuq_plate.png)）。尾灯/车灯是夜间"看得见车牌、读不出字"的直接原因。
3. **白天为什么也可能翻车**：本数据集白天没有出现"整块车牌削顶"的极端样（多云/正午蓝牌过曝 0–9.6%），但固定 EV 的白天风险是**量级问题**：夜间正确曝光 `1/50+ISO115` 对应 EV100≈5.4；正午阳光在 f/1.8 下正确曝光约 1/8000 s（ISO100），相差 **约 7.3 档**，若同一套参数进入白天会整体过曝；反过来为了白天高光压曝光，夜间车牌 ROI 会掉到 p50 **54–104 灰阶**、对比度逼近下限。数据集内白天的真实失效是**逆光/桥下 + 小目标**：桥下 62 px 车牌字符-底色差只有 **33**、不可读（[证据](crops/bridge_01m22s_far_plate.png)）。
4. **车牌可读的经验区间**（18 个车牌 ROI，4K 原生）：
   - 车牌宽度：可读 **≥ 88 px**（本集最窄可读 88 px），**60–88 px 为不稳定区**（本集 62 px 样失败），**< 60 px 不可读**；
   - 字符-底色亮度差（Otsu 两类中位差）：可读 **≥ 36 灰阶**（多数 54–145），**< 25 灰阶不可读**（红浸染样 10–19）；
   - 局部对比度 p90-p10：可读 **≥ 45**（多数 63–177），红浸染失败样 **28–39**；
   - 过曝比例（任一通道 >240）：大牌（≥200 px）可容忍到 **23%**（蓝通道削顶但字符仍可辨），中小牌建议 **≤ 10%**；过曝比例**单独不能判可读**，必须与字符-底色差联用；
   - 锐度：可读样本 Tenengrad **6.0×10³–1.0×10⁵**、水平边缘 10–90% 宽度 **0.6–2.8 px**（个别大牌 5.2 px）；但眩光样本（对比度崩塌）边缘宽度反而小，**不能用锐度单独判定**。
5. **运动模糊在什么快门/车速下毁牌**：以"曝光期间车牌相对位移 ≤ 字符笔画宽（≈20 mm）"为可读判据，**1/50 s 只允许相对速度 ≤ 3.6 km/h；1/200 s ≤ 14 km/h；1/500 s ≤ 36 km/h；1/1000 s ≤ 72 km/h**。本集实测：同速跟车的车牌 0.5 s 内只移动 **0–4 px**（像面速度 0–8 px/s，相对速度≈0），所以在 1/50 s 下依然锐利；而 20:18:25 横穿通过的出租车在 1/50 s 下被拉出 **40–70 px 拖影**，车牌不可辨（[证据](crops/night_app_02m57s_taxi_blur.jpg)）。

## 2. 方法

1. **找车牌**：对目标时刻 `ffmpeg -ss <t> -i <video> -frames:v 1 -pix_fmt rgb24 out.png` 抽全分辨率帧；用颜色掩膜（蓝牌 Hue 95–140 / 绿牌 25–128 OpenCV 量纲）+ 形态学闭运算 + 连通域得到候选；再按"7 字符白字行"做局部精定位（字符连通域按字高/间距聚合成行，按车牌 440:140 展开）。少量斜视/强眩光样本用网格叠加人工校准，bbox 误差约 ±5–10%。
2. **量化**：在 4K 原生 ROI 上计算（见 §3 定义）。所有 ROI 均取"车牌本体"（人工确认框住整块牌，含白边）。
3. **运动模糊**：在同一视频相邻时刻抽帧，用 ROI 作模板做 `TM_CCOEFF_NORMED` 匹配位移，得到像面速度；再结合水印快门换算曝光期拖影。夜间 App 车速由水印 GPS 坐标差分为约 28–35 km/h。
4. **明暗突变**：对每段素材按 2 fps 抽取 1280 宽帧，统计整帧平均亮度与逐 0.5 s 跳变。

## 3. 指标定义（全部 0–255 灰阶）

- `plate_w × plate_h`：车牌 ROI 宽高（px，原生分辨率）。
- `p10/p50/p90`：ROI 内 Rec.601 亮度分位。
- `over240`：ROI 内 **任一 RGB 通道 > 240** 的像素占比（用于捕捉"单通道削顶式过曝"，如蓝牌只看 B、绿牌只看 G、尾灯只看 R）。
- `contrast = p90 - p10`：局部对比度。
- `bg_glyph_delta`：ROI 内 Otsu 二值化后"亮类中位亮度 − 暗类中位亮度"（蓝牌=白字 vs 蓝底；绿牌=浅绿底 vs 深字）。**该指标对"字符是否还能从底色里分离出来"最敏感。**
- `Tenengrad`：ROI 内 Sobel 梯度平方均值（每像素），4K 车牌尺度的锐度参考。
- `edge_width_px`：ROI 中部 50% 行的亮度剖面上，最强竖直边缘的 10–90% 上升宽度（px），越大越糊。
- `scene_p50 / scene_p99`：车牌邻域（3 倍车牌框）与整帧的高光参考。

## 5. 失败模式分类

### F1 夜间固定曝光 + 暗部压缩（本项目 App）
- 证据：`night_app.mp4` 全程水印 `1/50 ISO 115`（[水印图](crops/night_app_watermark_1-50_ISO115.jpg)）；全帧平均亮度 12.2–106.2（中位 30.9），旧 DVR 同场景 49.6–75.6（中位 67.5）。
- 量化：**暗部整体暗 2.2 倍**，高光 p99 相当（185 vs 177）→ 8-bit 动态范围被压扁。以 20:16:58 帧为例：**50.8% 像素 <30 灰阶**（旧 DVR 夜间素材 15.9%，多云/正午/桥下白天素材仅 0.4–3.2%）——地面、车身、远处车辆基本沉入黑场。
- 影响：车牌 ROI 在夜间并不一定暗（近处反光牌 p50 98–141），但**一旦车距 >8–10 m，车牌就沉入暗部，无任何可恢复信息**。

### F2 夜间车牌过曝（单通道削顶 + 光幕）
- 证据：[night_app_00m03s_ahead](crops/night_app_00m03s_ahead_plate.png)（蓝通道 23.3% >240，仍可读）；[night_app_01m51s_oex](crops/night_app_01m51s_oex_plate.png)（绿通道 12.3% >240，可读）；对比 [night_app_01m30s_yuq](crops/night_app_01m30s_yuq_plate.png)（字符-底色差 19，不可读）。
- 量化：**通道削顶比例 8–23%** 是夜间牌照的典型值；可读与否取决于"削顶后字符-底色差是否仍 ≥35 灰阶"。
- 影响：白天蓝牌过曝 0–9.6% 尚可读；夜间反光会把通道打满，**同一过曝比例下夜间更容易粘连**（因为底色也变亮）。

### F3 尾灯/车灯红光浸染（veiling glare）
- 证据：[night_app_01m27s_yuq](crops/night_app_01m27s_yuq_plate.png)（对比度 28，字符-底色差无法分离）、[night_app_01m45s_glare](crops/night_app_01m45s_glare.jpg)（直射眩光帧，帧均值 23→106）。
- 量化：同一车牌在无浸染时字符-底色差 59–65，浸染后 **19（16:58）→ 无法分离（16:55）**；对比度 73 → 39 → 28。
- 影响：这是夜间"看得见车牌、读不出字"的主因。**单纯提高曝光会更糟**（光幕更亮），只能靠缩短曝光/HDR/局部色调映射。

### F4 白天逆光/桥下欠曝 + 小目标
- 证据：[bridge_02m56s_*](crops/bridge_02m56s_chev_plate.png)（可读）与 [bridge_01m22s_far](crops/bridge_01m22s_far_plate.png)（62 px，不可读）。
- 量化：桥下车牌对比度 63–85、字符-底色差 36–67；到 62 px 宽时对比度 58、差 33。**白天可读下限落在 60–90 px 宽度区间。**
- 影响：白天不需要"高光保护"，需要的是**保证车牌所在局部曝光 + 限制最小目标尺寸**；车牌优先 AE 的 ROI 若锁在阴影车牌上，会推高曝光导致天空/高光过曝（正午 van 样已出现 9.6% 过曝）。

### F5 明暗突变（桥下渐变 vs 车灯突跳）
- 桥下（afternoon 4K）：整帧平均亮度 73.6–103.3，逐 0.5 s 最大跳变 **10.0**（14:09:58 附近），无 >15 的突变 → **渐进过渡，自动 AE 可跟**（[曲线](crops/afternoon_bridge_luma_curve.png)）。
- 夜间 App：20:16:25–37 与 20:17:04–08 出现 **+89.5 / −44.8 灰阶/0.5 s** 的跳变（车灯直射、进出强光区），是全数据集唯一的强突变（[曲线](crops/night_app_luma_curve.png)）。
- **结论：本数据集没有隧道素材**；明暗突变风险主要来自夜间车灯直射，而非隧道。

### F6 运动模糊
- 证据：[night_app_02m57s_taxi_blur](crops/night_app_02m57s_taxi_blur.jpg)：20:18:25 横穿通过的出租车在 1/50 s 下整车/尾灯拉成 **40–70 px** 拖影，车牌不可辨。
- 对照：跟车/排队场景车牌 0.5 s 位移仅 **0–8 px**（相对速度≈0）→ 1/50 s 下拖影 <0.2 px，锐利可读。
- 结论见 §7 表：**1/50 s 只适合"相对速度 ≤3.6 km/h"的车牌**；夜间凡是横穿/对向/路边静止车牌，1/50 s 都会毁牌。

## 6. 车牌可读阈值建议（经验值）

基于 18 个 4K 车牌 ROI + 4 个失败样（红浸染、运动模糊、过小、眩光），建议自适应曝光算法使用**组合判据**，并给出优先级：

| 判据 | 可读 | 勉强 | 不可读 | 说明 |
|---|---|---|---|---|
| 车牌宽度（4K 原生） | ≥ 88 px | 60–88 px | < 60 px | 与跟车距离强相关；1080p 视频按 0.5× 折算（≥44 px） |
| 字符-底色亮度差（Otsu 两中位差） | ≥ 45 | 25–45 | < 25 | **最可靠的单指标**；红浸染/通道削顶都会把它打下来 |
| 局部对比度 p90-p10 | ≥ 63 | 45–63 | < 45 | 可用于快速筛选 |
| 过曝比例（任一通道 >240） | ≤ 10%（中小牌）/ ≤ 25%（≥200 px 大牌） | 10–35% | > 35% | 必须看"哪个通道"：蓝牌看 B、绿牌看 G、尾灯看 R |
| 水平边缘 10–90% 宽度 | ≤ 2.8 px（大牌可放宽至 ~5 px） | 2.8–6 px | > 6 px（或明显拖影） | 与运动模糊/失焦相关；眩光样会给出"假性好值"，需与字符-底色差联用 |
| 锐度 Tenengrad | ≥ 6×10³ | 3.5–6×10³ | — | 大小/噪声敏感，仅作辅助 |
| 背景（车牌邻域）亮度 p50 | 47–141（数据集内可读样实际范围） | — | — | **非判别量**：不可读样（76–92）与可读样（47–141）重叠，不能单靠背景亮度判断可读性 |

**优先级建议**：先保证尺寸（>88 px，否则任何曝光都救不了）→ 再保证字符-底色差 ≥35（曝光/增益的第一目标）→ 然后限制单通道过曝 ≤10–25%（避免削顶粘连）→ 最后用边缘宽度把运动模糊挡在门外（快门约束，见 §7）。

**为什么"固定 EV"两难**：
- 夜间正确值 `1/50+ISO115`（EV100≈5.4）在正午阳光（f/1.8 需 ≈1/8000 s，ISO100）下**过曝约 7.3 档**；
- 反过来，若为白天高光把曝光压低，夜间车牌 p50 只有 54–104 灰阶、对比度贴近下限；
- 白天内部本身也有 2–3 档跨度（桥下阴影 vs 天空），夜间内部有 **约 3 档**（帧均值 12.2–106.2，约 3.1 档）。**单一固定曝光必然在某一端失效**，这就是需要"场景分类 + 车牌 ROI 测光 + 高光保护"的原因。

## 7. 运动模糊：模型、实测与快门/车速表

### 7.1 模型

车牌物理宽度 440 mm（=0.44 m），像面上宽 `W` px，则比例 `W/0.44` px/m。曝光期间车牌相对像面速度 `v`（m/s）、快门 `t`（s），拖影像素数：

```
blur_px = W × v × t / 0.44
```

可读判据按"拖影不超过字符笔画宽（≈20 mm）"：
- **可读**：`v·t ≤ 0.020 m`（拖影 ≤ 1 笔画）
- **勉强**：`0.020 < v·t ≤ 0.050 m`
- **不可读**：`v·t > 0.050 m`（拖影 ≥ 2.5 笔画）

（若用"拖影 ≤ 0.1 车牌宽"这一更宽松判据，则对应 `v·t ≤ 0.044 m`；两种判据差异见下表。）

### 7.2 实测

| 场景 | 车牌 | 0.5 s 像面位移 | 相当于像面速度 | 1/50 s 拖影 | 目视 |
|---|---|---|---|---|---|
| 0919 多云停车排队（0 km/h） | 陕U·FC810 | 0 px | 0 px/s | 0 px | 锐利 |
| 0925 黄昏停车排队（0 km/h） | 苏A·B71305 | 0 px | 0 px/s | 0 px | 锐利 |
| noon 12:44（1 km/h） | 沪B·FV785 | 1 px（纵向） | 2 px/s | <0.1 px | 锐利 |
| afternoon 桥下 51 km/h 跟车 | 远处绿牌车 | 3 px | 6 px/s | 0.1 px | 7 字符可辨（但太小） |
| night_app 20:16:55 跟车 ≈34.6 km/h | 豫Q·052M1 | 4 px（纵向 18 px） | 8–36 px/s | 0.2–0.7 px | 字符模糊（主因是红光浸染，非运动） |
| night_app 20:18:25 横穿出租车 | 出租车后侧 | 连续帧 13 px/41.7 ms ≈ 312 px/s（近距离下更大） | 数百至数千 px/s | **40–70 px** | 不可辨 |

> 车速来源：night_app 水印 GPS 差分（20:16:43→49 约 28 km/h；20:16:49→55 约 34.6 km/h；20:16:55→58 降到 11 km/h）。**结论：本数据集里"能读的车牌"几乎都是与自车同速的跟车/排队牌（相对速度≈0），真正被运动模糊毁掉的是横穿/对向/静止目标。**

### 7.3 快门/相对速度表（可读上限，按 v·t ≤ 20 mm）

| 快门 | 可读上限相对速度 | 勉强上限（v·t≤50 mm） | 1/50 对比 |
|---|---|---|---|
| 1/50 s（20 ms） | **3.6 km/h** | 9 km/h | — |
| 1/100 s（10 ms） | 7.2 km/h | 18 km/h | 2× |
| 1/200 s（5 ms） | 14.4 km/h | 36 km/h | 4× |
| 1/500 s（2 ms） | 36 km/h | 90 km/h | 10× |
| 1/1000 s（1 ms） | 72 km/h | 180 km/h | 20× |

推论：
- **夜间 1/50 s 只能保住"和自车同速"车牌的清晰度**；只要目标有 ≥9 km/h 的相对速度（横穿电动车、对向车、路边停着的车牌），就会进入不可读区。
- 夜间要兼顾"车牌可读 + 相对运动"，需要 **1/200 s 以上**（对应 ISO 提高 4×，或 HDR/多帧合成），这与 1/50 ISO115 的现状相距 2 档以上。
- 白天快门通常在 1/500–1/1000（阳光充足），相对运动容限 36–72 km/h，所以**白天并不怕运动模糊，怕的是逆光/小目标**。

## 8. 明暗突变与隧道

- **桥下（可复现）**：`afternoon.mp4` 14:08:54–14:11:54 全程在高架下，整帧平均亮度 73.6–103.3、逐 0.5 s 最大跳变 10.0 → 温和的明暗起伏；车牌 ROI 的 p50 跟随场景 74–89。**这是"渐变过渡"，普通 AE 能跟，但需要防止测光被出口天空拉高而让车牌欠曝。**
- **夜间车灯直射（强突变）**：`night_app.mp4` 20:16:25–37 与 20:17:04–08，帧均值 16.7→106.2（+89.5/0.5 s）再到 12.2，属"点光源进入视野 + 光幕"型突变。**这种突变无法用"慢速 AE 平滑"处理，必须靠高光保护 + 快速回退。**
- **隧道：本数据集没有隧道素材**（全部素材的亮度时间序列都不存在"持续 >2 s 的极暗段 + 两端突变"模式）。隧道特有的"入口黑、出口白"瞬态**未取证**，建议后续用实拍隧道素材补。

## 9. 对自适应曝光算法的直接启示

1. **场景分类优先级**：白天多云/正午 → 以"高光保护 + 车牌 ROI 对比度"为主；黄昏 → 提前介入高光保护（光晕已出现）；夜间 → 以"字符-底色分离"为第一目标，允许背景略暗。
2. **测光 ROI**：不能只用全画面平均。夜间全帧平均 30.9 而车牌 ROI 75–153，偏差 2–5 倍；应把车牌候选框（或车道中央下方高反光矩形）作为加权 ROI，并限制 ROI 被大面积暗背景稀释。
3. **控制量优先级**：夜间先动**快门/增益组合**（1/50→1/200 换取运动容限）再动 ISO；白天优先**压高光**（避免车牌白字削顶）而不是提亮暗部。
4. **滞回与失效兜底**：本次实测的强突变（+89.5 灰阶/0.5 s）远超人眼舒适区，建议 AE 带"高光优先 + 单帧限速 + 3–5 帧滞回"；当车牌 ROI 字符-底色差 < 25 或宽度 < 60 px 时，算法应放弃"等车牌"策略，回退到全局安全曝光。
5. **可验收指标**：用 §6 的组合判据做回归测试（字符-底色差 ≥35、宽度 ≥88 px、通道过曝 ≤25%），比只看整帧亮度更贴合"车牌可读"目标。

### 10.2 ROI 量化（一次算完所有指标）

```python
import cv2, numpy as np
img = cv2.imread('/tmp/frame.png'); x,y,w,h = 1290,1067,215,68     # 换成目标 ROI
roi = img[y:y+h, x:x+w]
g = cv2.cvtColor(roi, cv2.COLOR_BGR2GRAY).astype(np.float32)
flat = g.ravel()
p10,p50,p90 = [np.percentile(flat,q) for q in (10,50,90)]
over = float((np.maximum.reduce([roi[:,:,i].astype(np.float32) for i in range(3)])>240).mean())
thr,_ = cv2.threshold(g.astype(np.uint8),0,255,cv2.THRESH_BINARY+cv2.THRESH_OTSU)
delta = float(np.median(flat[flat>=thr]) - np.median(flat[flat<thr]))
lap = cv2.Laplacian(g, cv2.CV_32F, ksize=3)
ten = float((cv2.Sobel(g,cv2.CV_32F,1,0,3)**2 + cv2.Sobel(g,cv2.CV_32F,0,1,3)**2).mean())
print(dict(w=w,h=h,p10=p10,p50=p50,p90=p90,over240=over,contrast=p90-p10,
           delta=delta, tenengrad=ten, lapvar=float(lap.var())))
# 通道削顶（判断是哪个通道过曝）
b,gg,r = [roi[:,:,i].astype(np.float32) for i in range(3)]
print('R/G/B >240:', [round(float((c>240).mean())*100,1) for c in (r,gg,b)])
```

## 11. 局限与未覆盖

1. **无隧道素材**：明暗突变只覆盖"桥下渐变"与"夜间车灯突跳"，隧道入口/出口未取证。
2. **快门/ISO 只有夜间 App 素材有**（水印 `1/50 ISO 115`）；DVR 素材无 EXIF，运动模糊只能定性 + 模板匹配估计。
3. **ROI 由半自动检测 + 人工校准**，bbox 误差约 ±5–10%；夜间强眩光/斜视样本（黄昏 tesla、豫Q 系列）指标偏差更大，已尽量在表格中区分"勉强/不可读"。
4. **车速只对 night_app 由 GPS 差分估计**（≈28–35 km/h），DVR 素材车速来自画面水印（0–69 km/h），精度有限。
5. **没有对向远光灯直射车牌**的样本（只有尾灯/旁车灯/近距车灯直射），"逆光"样本是桥下天空亮/地面暗。
6. **白天"整块车牌欠曝到不可读"没有出现**：本集白天失败主要是小目标（62 px）与斜视；若要论证白天欠曝阈值，需补充"正对太阳 / 隧道出口"素材。
7. **过曝判据是"任一通道 >240"**，对通道削顶敏感；未做 RAW/10-bit 对照，无法判断削顶是传感器饱和还是编码/色调映射造成。
8. `night_app.mp4` 为 VFR（平均约 24 fps），相邻帧间隔不均匀，模板匹配的 dt 已按实际抽帧时间差取值。
9. 素材版权/隐私：证据图仅裁车牌区域，未放整帧 4K；原始素材保留在 `/tmp/ae-analysis` 与 `~/dsh/default`，未修改、未删除。
