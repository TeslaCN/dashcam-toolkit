## 0. 结论速览（最重要的 14 条）

1. **`CONTROL_AE_REGIONS` 不是“高光优先”API。** 它只定义“哪些区域参与测光、权重多少”，不规定测光算法是平均值、加权平均还是高光保持；是否真的尊重这些区域由厂商 HAL 决定。已知部分厂商实现有问题（Nexus 5X 可用、Galaxy Note 5 忽略），因此**不能把夜间车牌方案押在系统 AE regions 上**。[A1][A42]
2. **EV 补偿是全局偏置，不是局部高光保护。** 官方保证 LIMITED/FULL 设备至少 ±2 EV，步进由 `CONTROL_AE_COMPENSATION_STEP` 决定；P30 的 0.5 EV / ±2 EV 目前是代码与任务背景的说法，需用 `CameraCharacteristics` 打印证据固化。夜间车牌与路面差 3–10 EV，单靠 EV 要么车牌过曝、要么路面全黑。[A2][A9][A10][D2]
3. **手动 `AE_MODE_OFF` + `SENSOR_EXPOSURE_TIME` / `SENSOR_SENSITIVITY` 在 P30 上已实测可用**（当前项目的手动模式与车牌优先草案都基于它）。官方语义清楚：仅当 AE/Control mode 为 OFF 时生效；HAL 可能把请求值夹到最近支持值，最终值必须从 `CaptureResult` 回读；AWB/AF 行为在 AE OFF 时是设备相关的，建议锁 AWB/AF 或固定焦点。[A3][A4][A17][D3]
4. **逐帧更新的开销本身不大，但“生效”有 1–3 帧流水线延迟。** `setRepeatingRequest` 是轻量调用；真正的问题是 HAL 的 exposure/gain 收敛、3A 流水线和编码器缓冲。官方 EV 文档明确“改 EV 后相机可能要若干帧才到新目标”；现有 320×240/6 Hz 测光 + 150 ms 节流意味着控制带宽约 6–7 Hz，隧道/明暗突变的收敛会偏慢。[A2][A23][D3]
5. **夜间车牌过曝的物理根源是逆反射 + 近共轴照明。** 中国号牌反光膜标准（GA 36-2018/GA 666-2018）要求 0.2° 观测角、5° 入射角下逆反射系数最小值 40 cd/(lx·m²)（白色 60）；而漫反射白漆约 0.8/π ≈ 0.25，同照度下**车牌可比白漆亮约 150 倍（~7 EV）**；与沥青（ρ≈0.1）比可差 ~1000 倍（~10 EV）。观测角变大时逆反射系数快速下降（1°30′ 时仅 3.5），所以实际倍率取决于相机/车灯/车牌的几何，需实测标定。[S1][P1][P2][S6]
6. **运动模糊的硬约束是“相对模糊”，与变焦/距离无关：** 车牌宽度方向相对模糊 ≈ `v_lat · t_exp / 0.44 m`。横向相对速度 5 m/s 时，1/100 s 模糊占车牌宽度 11.4%，基本不可读；1/500 s 为 2.3%，1/1000 s 为 1.1%。头对头接近时主要是径向膨胀，10 m/60 km/h/1/100 s 仅约 1.7% 宽度膨胀，1/100–1/250 可接受；近距离（5 m）或横穿/转弯才需要 1/500–1/1000。[P7][P8]（本文附录推导）
7. **车牌像素门槛：** 中国 GA/T 833 要求自动识别图像中车牌水平像素 **>100 px**；Milestone/Mobotix LPR 手册给出 130 px（30.5 cm 美国牌、停止/无隔行）、170 px（52 cm 欧洲牌）、运动隔行 215/280 px，笔画至少 2.7 px/笔画，文字与背景像素差 ≥15。工程上中国 44 cm 蓝牌建议 ≥120–150 px 才稳。[S2][S3][S4]
8. **P30 的分辨率是车牌识别的瓶颈：** 按 27 mm 等效、1080p 全宽估算 `f_px≈1440`，10 m 处 44 cm 车牌只有约 **63 px 宽**（低于 100/130 px 门槛）；5 m 才约 127 px。4K 理论翻倍（10 m≈127 px），但本机 HAL 的 4K 录像组合不稳定（README 记录会 `ERROR_CAMERA_DEVICE(4)`），因此现实路线是 **1080p + 2× 数字变焦 或 2.1× 长焦**（长焦视频能力需验证），而不是依赖 4K。[D1][D2][D3][V12]
9. **30 fps 视频下，曝光时间必须 ≤33.3 ms；50 Hz 照明下只能用 10 ms 的整数倍。** 即 30 fps 且曝光 ≤33.3 ms 时，50 Hz 安全档是 10/20/30 ms（1/100、1/50、1/33.3），**1/60=16.7 ms、1/30=33.3 ms、1/125=8 ms、1/250=4 ms 都不是 50 Hz 安全档**；手动模式官方明确说 `CONTROL_AE_ANTIBANDING_MODE` 不再生效，必须应用自己保证。中国电网 50 Hz（100 Hz 纹波），这条是夜间路灯/隧道照明的硬约束。[A6][A22][S9]
10. **HDR/WDR 是行车记录仪的主流解法，但 P30 第三方基本拿不到：** 厂商用 DOL HDR/Clear HDR/双帧不同快门合成 30 fps HDR（Viofo、Thinkware、BlackVue、70mai、盯盯拍等）；传感器级 HDR（DCG/split pixel/LOFIC）可达 120–140 dB 并带 LED 闪烁抑制（LFM）。但 Camera2 HDR 视频 API 要求 **Android 13/API 33 + 10-bit 传感器**；CameraX/Camera2 extensions 官方注明只覆盖预览与拍照、**不覆盖视频**；P30 是 API 29，系统层没有这条路径。[A24][A25][V1][V4][V7][V8][V9][V18]
11. **10-bit、RAW、Reprocessing 都不能用于 P30 的 30 fps 视频曝光决策：** 10-bit 是 API 33+ 能力（`DYNAMIC_RANGE_TEN_BIT`）；RAW 是静态拍照能力且 P30 主摄第三方 RAW 据报道不可用（OpenCamera ticket）；reprocessing 是 API 23+ 的 ZSL 静态拍照路径，且只有 JPEG/降噪/边缘等少数控制生效，不能“拍完再救回过曝”。[A16][A18][A19][A20][A25][V14]
12. **Huawei 私有 tag 的正确态度：可探测、不可依赖。** AOSP 文档说 vendor tags 会通过 `CameraCharacteristics.getKeys()` 对 public camera2 API 可见；应用可以枚举 `getKeys()` 里 `com.*` 的键并尝试读取。但 `hdrMovieSupported`、`sensorHdr3PartySupported`、`availbaleSupernightIso`、`superHighISOExposureTimeValue` 没有公开语义/稳定性承诺，第三方是否能设置、HAL 是否执行都**未证实**；只能作为 feature flag 实验，不能进生产主路径。[A27][A28][D7]
13. **推荐主路线：单曝光 + 车牌 ROI 优先 + 高光保护的手动闭环 + 系统 AE 兜底；HDR/WDR 不作为 P30 第三方主路径。** ROI 用自建 YUV 测光（已有基础）而不是系统 AE regions；优先保证车牌亮色区域不过饱和（p99/裁剪率约束），其次保证路面不黑到不可用；曝光时间优先用于高光/运动，ISO 用于补亮度；加入场景状态机、50 Hz 量化、滞回/阻尼、失效兜底。[A1][P6][P9][D3][D4]
14. **当前 `PlateAeController` 草案方向正确，但有几个 P0 风险需要先修：** ①快门档位表里的 1/60、1/30、1/125、1/250 不是 50 Hz 安全档，与注释“兼顾 50Hz”矛盾；②“过曝先降 ISO、ISO 到底再缩快门”可能救不了传感器满阱饱和，需实验证明；③运动上限只用本车速度，无法区分头对头/横穿，也漏掉低速时被超车/横穿；④960×540 测光下 10 m 车牌只有约 31 px 宽，代理块可能根本看不到字符结构；⑤测光流创建失败时车牌模式会停在 seed 曝光，没有自动回退。详见第 6 节。[D4]

### 1.4 本文计算假设（重要，影响所有数字）

- P30 主摄 27 mm 等效，按 35 mm 全画幅水平 FOV 计算：`HFOV = 2·atan(36/(2·27)) ≈ 67.4°`。
- 1080p 全宽像素焦距：`f_px(1080p) = 1920 / (2·tan(HFOV/2)) ≈ 1440 px`；4K/2× 变焦约 2880 px；2.1× 长焦约 3024 px。
- 中国蓝牌/黄牌宽 440 mm；新能源牌 480 mm（本文按 440 mm 算，新能源结果约 +9%）。
- 车牌 ROI 亮度/图像统计均按 8-bit luma 0–255 表述；**相机 YUV 可能是 limited range（16–235）或经过色调映射**，绝对阈值必须用实际录像帧/测光帧标定 `[待验证]`。
- 夜间路面照度、车牌照度用变量 `E` 表示；比值计算与 `E` 无关，绝对亮度例子只是数量级演示。
- 实际观测角/入射角由相机、车灯、车牌几何决定；本文用标准表 + 几何估算，最终以 task-7 取证和实车测量为准。

## 2. Android Camera2 能力边界（问题 1）

### 2.1 `CONTROL_AE_REGIONS`：可用性、语义、厂商差异

**官方语义 `[有出处]` [A1]：**

- 它是“用于 AE 调整的测光区域列表”，每个区域 `MeteringRectangle` 带权重 `[0,1000]`。
- 权重的含义是“区域内每个像素的权重”；**同样权重下，面积越大的区域影响越大**；区域可重叠，重叠处权重相加；权重 0 的区域被忽略；所有区域权重为 0 时回到相机默认测光行为。
- 最大区域数由 `CONTROL_MAX_REGIONS_AE` 决定；`maxRegionsAe=0` 时该 key 不可用（Optional）。
- 坐标系是 `SENSOR_INFO_ACTIVE_ARRAY_SIZE`（或 pre-correction active array，若支持畸变校正）；与 `SCALER_CROP_REGION` 相交，超出 crop 的部分被忽略；API 30 起坐标语义还受 `CONTROL_ZOOM_RATIO` 影响。**在 API 29 上用 `SCALER_CROP_REGION` 做数字变焦时，ROI 必须做 crop→active array 的坐标映射。**
- **文档没有规定测光算法是平均值、中心加权还是高光优先，也没有规定目标亮度。** 这些完全由厂商 HAL/3A 决定。因此 `[推断]`：它不是“高光优先 AE”，不能保证保护逆反射车牌高光。

**厂商实现差异 `[有出处]` [A42]：**

- StackOverflow 问题：同一个 AE region 在 Nexus 5X 生效，在 Samsung Galaxy Note 5 被忽略；回答者称“很多厂商对这部分文档实现很差”，并给出一个 workaround：把矩形从 active array 边缘内缩 1 px、底部减 2 px（避免越界）。这说明：
  - 返回的 `CaptureResult.CONTROL_AE_REGIONS` 可能只是“回显/裁剪”，不代表 HAL 真正按它测光；
  - 需要设备特定测试，不能跨机型假设；
  - 区域越界/贴边可能被整块忽略。

**P30 上的状态 `[待验证]`：**

- `CONTROL_MAX_REGIONS_AE` 是否 ≥1；草案称“最多 1 个”，但未见公开/日志证据。
- 区域在 `TEMPLATE_RECORD` 视频请求里是否生效；是否被人脸检测/场景模式覆盖；权重是否被尊重。
- 在 1×/2× crop 下 ROI 映射是否正确。
- 夜间高光场景下，HAL 的测光目标是否会把车牌拉回过曝（很可能，因为目标亮度是全局统计）。

**建议：**

- **不要**把 AE regions 作为夜间车牌优先的主执行器；可以作为系统 AE 兜底模式下的“提示”，且必须用 `CaptureResult` 回显和实际曝光变化双重验证。
- 主路径用自建 YUV 测光 + 手动曝光，ROI 完全可控（当前项目已有基础）。
- 如果测试证明 P30 的 AE regions 有效，价值主要在：白天逆光时把测光从天空拉回下方车牌/路面；夜间仍不足以解决 3–10 EV 的局部高光。
- 测试方法：同一场景分别 (a) 无 region、(b) 车牌小矩形 weight=1000、(c) region 全 0，记录 `CaptureResult.SENSOR_EXPOSURE_TIME/SENSOR_SENSITIVITY` 和实际画面亮度；若 (b) 与 (a) 无可重复差异，判定 HAL 不响应。

**结论：** `CONTROL_AE_REGIONS` 是“加权测光区域”，不是高光保护；第三方可用但厂商实现差异大，P30 未证实。**方案不能依赖它。**

### 2.2 `CONTROL_AE_EXPOSURE_COMPENSATION`：步进、范围、限制

**官方语义 `[有出处]` [A2][A9][A10]：**

- 单位是补偿步数，步进由 `CONTROL_AE_COMPENSATION_STEP` 定义；范围由 `CONTROL_AE_COMPENSATION_RANGE` 定义。
- 对 LIMITED/FULL 设备，如果支持 EV 补偿，范围必须至少覆盖 **−2 EV 到 +2 EV**；LEGACY 可更小；`[0,0]` 表示不支持。
- 只在 `CONTROL_AE_MODE != OFF` 时有效；即使 `CONTROL_AE_LOCK=true`，改 EV 仍会生效。
- 改 EV 后相机可能“若干帧”才到新目标，期间 `CONTROL_AE_STATE=SEARCHING`，到目标后变 `CONVERGED`（或 `LOCKED`/`FLASH_REQUIRED`）。
- **EV 是全局目标亮度偏置**；对“车牌局部高光”没有针对性。

**P30 的 0.5 EV / ±2 EV：**

- 代码 `Settings.java:48` 注释与 UI 都按 0.5 EV、±2 EV 设计；`applyEvCompensation` 会读取设备 step/range 做换算（`RecordingSession` 约 :846）。
- 但“0.5 EV/±2 EV”目前是任务背景/代码假设，**没有看到 `CameraCharacteristics` 打印证据**；必须实机复核。若实际 step=1/3 或 range 更大，UI/换算要相应调整（代码本身会按设备值 clamp，但 UI 标签会误导）。
- `[待验证]` P30 的 EV 是否在视频模板下被 HAL 尊重；某些厂商只对拍照生效。

**为什么 EV 不能作为夜间主方案：**

- 第 3 节的亮度比表明，夜间同一帧里车牌与路面的亮度差可达 3–10 EV；EV 只能整体平移，不能同时把车牌压到不饱和、把路面抬到可见。
- 把 EV 调到 −1/−2 可以保住车牌，但路面/车身会黑；调到 0/+1 路面正常，车牌必过曝。
- EV 的另一个问题是“目标由 3A 决定”，HAL 可能把高光当噪声丢弃，EV 的响应非线性且不可预测。

**建议：**

- 自动模式兜底时，夜间用 EV −0.5 到 −1.0 做粗保护，但明确它不是车牌优先方案。
- 主方案用手动曝光闭环；EV 只在自动 AE 兜底、或“白天逆光下把测光拉回下方”时使用。
- 记录每次 EV 的 `CaptureResult` 实际曝光/ISO，验证 HAL 是否响应。

**结论：** EV 是全局偏置，官方最小 ±2 EV、步进设备相关；P30 0.5 EV/±2 EV 需实机固化。**EV 单独无法解决车牌局部过曝。**

### 2.3 `CONTROL_AE_MODE_OFF` + 手动曝光：可行性、开销、30 fps 约束

**官方语义 `[有出处]` [A3][A4][A5][A7][A17]：**

- `AE_MODE_OFF`：相机的 AE 例程关闭，应用设置的 `SENSOR_EXPOSURE_TIME`、`SENSOR_SENSITIVITY`、`SENSOR_FRAME_DURATION` 被使用；但 AWB/AF 行为设备相关，建议把 AWB/AF 也关掉或先锁定。
- LEGACY 设备不支持 OFF，会强制回 ON；P30 能用，说明至少 LIMITED（且支持 MANUAL_SENSOR）。
- `SENSOR_EXPOSURE_TIME`：单位 ns；只对每个像素曝光时长；如果传感器不能精确支持，会**缩短到最近支持值**（不会加长）；最终值在 `CaptureResult` 中。仅当 `AE_MODE` 或 `CONTROL_MODE` 为 OFF 时生效。
- `SENSOR_SENSITIVITY`：ISO 12232 标准感光度；超出 `SENSOR_INFO_SENSITIVITY_RANGE` 会被 clamp；最终值在结果里；高于 `SENSOR_MAX_ANALOG_SENSITIVITY` 后可能混入数字增益。
- `SENSOR_FRAME_DURATION`：帧读出到下一帧读出的时长；HAL 会把 duration 夹到 `max(duration, exposureTime + overhead)`。**如果曝光超过帧间隔 + 开销，帧率会掉。**
- `CONTROL_AE_TARGET_FPS_RANGE`：只约束 AE，不约束手动曝光/帧时长。所以手动模式要自己保证曝光 ≤ 帧预算。
- `CONTROL_AE_ANTIBANDING_MODE`：手动模式下**不生效**；应用必须自己选不产生 banding 的曝光时间，可参考 `STATISTICS_SCENE_FLICKER`。
- 官方还给了自动→手动无闪烁切换流程：先 `AE_LOCK=true`，等到第一个 locked 的结果，把结果里的曝光/ISO 抄进手动请求，再切 `AE_MODE_OFF`。当前项目是直接以手动模式开会话，切换模式时值得按这个流程做。

**P30 可行性 `[项目事实]`：**

- 当前 App 的模式 1/2 都在用 `AE_MODE_OFF` + 逐帧设置；任务背景称实测可用（ISO 50–6400，曝光到 1/2000 或更短）。
- `RecordingSession` 在手动模式下设置 `CONTROL_MODE_AUTO` + `AE_MODE_OFF`，并逐帧 `setRepeatingRequest`；测光帧驱动 ISO/曝光更新。
- 需验证：实际 `SENSOR_INFO_EXPOSURE_TIME_RANGE` 下限、ISO 下限/上限、HAL 是否接受任意 ns 值、最终值回读是否与请求差很多。

**逐帧更新的开销 `[推断/待验证]`：**

- `setRepeatingRequest` 本身是轻量 Java/Binder 调用（每帧一次远小于曝光/编码开销）；真正的成本在 HAL 重新配置传感器/ISP 和 3A 流水线。
- 官方说改 EV 要“若干帧”收敛；手动 exposure/gain 的生效延迟未在公开文档量化。按手机 Camera2 经验通常 1–3 帧（33–100 ms），加上 6 Hz 测光节流，闭环总延迟约 0.15–0.5 s `[待验证]`。
- 当前 `handlePlateAe` 每 150 ms 才处理一帧（约 6.7 Hz），并只在 `out.changed` 时 `setRepeatingRequest`；控制带宽足够日常，但隧道 80 km/h（22 m/s）下 150 ms 走 3.3 m，可能偏慢。
- 逐帧更新不会导致掉帧的“直接”原因是：`setRepeatingRequest` 复用同一个 session/streams；但频繁改 exposure/gain 可能让 3A/ISP 抖动或让编码器码率波动，需长跑验证。

**30 fps 曝光预算：**

- 帧间隔 33.33 ms；曝光 + 传感器开销必须 ≤ 帧间隔，否则 HAL 会拉长 `SENSOR_FRAME_DURATION`，帧率下降。
- 建议显式设 `SENSOR_FRAME_DURATION = 1e9/fps`（33,333,333 ns @30fps），并监控实际 fps；不要只依赖默认。
- 50 Hz 安全档：10 ms、20 ms（30 fps 下 30 ms 也安全但只剩 3.3 ms 开销，需实测是否掉帧）；1/60、1/30 不是 50 Hz 安全档（详见第 5.6 节）。
- 夜间若用 20 ms 曝光，帧间隔仍 33.3 ms，理论 30 fps；但若 HAL overhead >13.3 ms 或 ISP 处理不过来，会掉帧。需实测。

**AWB/AF 风险：**

- AE OFF 时 AWB 仍可能是自动的（设备相关）；夜间车灯/路灯色温变化会导致白平衡漂移，影响车牌颜色识别（蓝牌/绿牌/黄牌）和 OCR。建议：固定 AWB 或锁定，至少在车牌优先模式中记录 AWB 状态；若 AWB 漂移严重，可考虑使用 `CONTROL_AWB_LOCK`/手动 gains（需 HAL 支持）。
- AF 在夜间低照度可能拉风箱；当前项目已有“固定无穷远”对焦模式，行车场景建议默认固定焦点（或先 AF 收敛再锁），避免车牌在景深内但被拉虚。

**结论：** 手动曝光在 P30 上可行，是主方案的正确基础；30 fps 下必须遵守 33.3 ms 预算和 50 Hz 量化；逐帧更新开销可接受，但生效延迟/掉帧/回读偏差必须实测；AWB/AF 要锁定或固定。

### 2.4 Huawei 私有 tag 与第三方 HDR 视频

**Huawei 私有 tag 是什么：**

- 任务背景给出的 `hdrMovieSupported`、`sensorHdrSupported`、`sensorHdr3PartySupported`、`availbaleSupernightIso`、`superHighISOExposureTimeValue` 来自 `dumpsys media.camera` 的 vendor tag 区；命名带明显拼写错误（`availbale`），不像公开稳定 API。
- 它们大概率对应 Huawei Camera HAL 的：
  - HDR 视频能力/开关（`hdrMovieSupported`）；
  - 传感器 HDR / 第三方 HDR 许可（`sensorHdrSupported`、`sensorHdr3PartySupported`）；
  - 超级夜景可用 ISO 列表（`availbaleSupernightIso`）；
  - 超高 ISO 模式曝光时间（`superHighISOExposureTimeValue`）。
- 以上语义是**根据名字的推测**，没有公开文档；`[待验证]`。

**第三方能否读取：**

- AOSP 相机文档明确：“The public camera2 API will always make the vendor tags visible via `CameraCharacteristics#getKeys`”（vendor tags 会通过 `getKeys()` 对 public camera2 API 可见）。[A27]
- 因此应用可以：`for (CameraCharacteristics.Key<?> k : cc.getKeys()) if (k.getName().startsWith("com.")) ...`，尝试 `cc.get(k)`。已有技术文章演示这种枚举 vendor key 的方法。[A28][A41]
- 但 `getKeys()` 只保证“可见/可读”，**不保证可写**。要设置 vendor request key，需要该 key 出现在 `CameraCharacteristics.getAvailableCaptureRequestKeys()` 里，且 HAL 真正执行；Huawei 私有 tag 很可能只用于 OEM 相机 App 的内部 session 参数，第三方 set 后可能被忽略或报 invalid request `[待验证]`。
- 稳定性风险：私有 tag 的 key 名/类型/语义随固件/EMUI 版本变化；Huawei 没有兼容性承诺；不同镜头/不同 camera ID 暴露的 tag 可能不同。

**P30 第三方能否启用 HDR 视频：**

- 公开 API：**不能**。Camera2 HDR 视频要求 API 33+ 且 10-bit 传感器；P30 是 API 29。[A24]
- CameraX/Camera2 extensions：官方明确“extensions 只覆盖 preview 和 image capture，不覆盖 video capture”；AndroidX 的扩展支持设备列表里 Huawei P30 系列出现在 HDR/Portrait 扩展支持中，但那是**拍照扩展**，不是视频 HDR。[A25][V13]
- 私有 tag：`[待验证]`。即使 `sensorHdr3PartySupported` 为 true，也不代表通过 Camera2 能打开一个稳定的 HDR 视频模式；可能需要在 `TEMPLATE_RECORD` 设置 vendor key，或需要 OEM 的 session 配置。没有公开成功案例。
- 华为 Camera Kit/超级夜景：华为开发者文档有“超级夜景”拍照流程（长曝光 + 回调），但这是**静态拍照**的 OEM 能力，不是实时视频 AE；且接入 HMS/Camera Kit 会引入生态与设备限制。[V16]（详见第 4.2 节）

**建议：**

- 生产主路径不依赖 Huawei 私有 tag。
- 可做一个独立 feature flag/实验：
  1. 枚举 `getKeys()`，把 `com.*` 键名/类型/值写入日志；
  2. 尝试读 `hdrMovieSupported`、`sensorHdr3PartySupported`、`availbaleSupernightIso`、`superHighISOExposureTimeValue`；
  3. 在 `TEMPLATE_RECORD` 上尝试设置 `sensorHdr3PartySupported` 类似开关（只在测试 APK）；
  4. 观察 HAL 是否报错、`CaptureResult` 是否回显、画面动态范围/帧率是否变化；
  5. 任何 crash/HAL error/帧率下降 → 放弃。
- **不要**把私有 tag 作为默认行为；不要在没有回退的情况下切换。

**结论：** 私有 tag 可探测、可读，但第三方可用性/可写性/稳定性均未证实；P30 第三方 HDR 视频在公开 API 下不可行。**不进入生产主路径。**

### 2.5 10-bit / RAW / Reprocessing / HDR 视频：为什么不能用于 30 fps

| 能力 | API/条件 | P30（API 29） | 能否用于 30 fps 视频曝光 | 依据 |
|---|---|---|---|---|
| 10-bit 输出 | API 33+，`REQUEST_AVAILABLE_CAPABILITIES_DYNAMIC_RANGE_TEN_BIT`，`REQUEST_AVAILABLE_DYNAMIC_RANGE_PROFILES`，HLG10 等 | 不支持（API 29 无这些 API） | 否 | [A19][A26][A24] |
| HDR 视频 | API 33+，10-bit 或更高传感器，动态范围 profile | 不支持公开 API | 否 | [A24] |
| RAW | `REQUEST_AVAILABLE_CAPABILITIES_RAW`；`RAW_SENSOR` 输出；静态高分辨率 | 主摄第三方 RAW 据报道不可用；即使可用也不是视频流 | 否 | [A16][V14] |
| Reprocessing | API 23+，`createReprocessableCaptureSession` + `createReprocessCaptureRequest`；ZSL 静态拍照；只有 JPEG/NR/edge 等控制生效 | 能力未知，即使有也不能逐帧重跑 30 fps 曝光 | 否 | [A18][A20][A21] |
| 高速度会话 | `CONSTRAINED_HIGH_SPEED_VIDEO`，≥120 fps，受限控制 | 未知；不解决曝光动态范围 | 否 | [A16] |
| 多帧 HDR（App 自合成） | 需要每帧不同曝光或更快读出；单 stream 输出会闪烁/掉帧 | 30 fps 下不可行（除非降低到 15 fps 或做离线融合） | 否（对实时 30 fps 单流） | [P1][V7] |

**Reprocessing 细节 `[有出处]` [A18][A20]：**

- `PRIVATE_REPROCESSING` 是 Zero Shutter Lag 拍照路径：一个输入 stream + 输出；重处理请求只对 JPEG、降噪、边缘等少数控制生效；其他控制被忽略。
- 它适合“先拍高分辨率，再按需重处理”，不适合“每帧根据测光结果重新决定曝光”。
- 对已经饱和的车牌，reprocessing 不能恢复被裁剪的高光信息（传感器满阱/ADC 已经截断）。

**结论：** 10-bit/RAW/reprocessing/HDR 视频都不能作为 P30 30 fps 视频的自适应曝光手段。**唯一现实路径是单曝光 + 曝光策略 + 光学/后处理。**

## 3. 车牌成像物理与曝光（问题 2）

### 3.1 逆反射：为什么夜间车牌会比周围亮

**中国号牌标准 `[有出处]` [S1]：**

- GA 36-2018 规定小型汽车号牌外廓 440 mm × 140 mm；号牌表面使用符合 GA 666-2018 的反光膜。
- 反光膜的逆反射系数最小值（节选，单位 cd/(lx·m²)）：

| 颜色 | 观测角 | 入射角 5° | 入射角 30° | 入射角 45° |
|---|---:|---:|---:|---:|
| 蓝/绿/黄 | 12′（0.2°） | 40 | 18 | 4.0 |
| 蓝/绿/黄 | 20′（0.33°） | 30 | 10 | 2.0 |
| 蓝/绿/黄 | 1°30′（1.5°） | 3.5 | 1.5 | 0.5 |
| 白色 | 12′ | 60 | 25 | 6.0 |
| 白色 | 20′ | 40 | 14 | 3.0 |

- 这张表说明两个关键点：
  1. **逆反射有强烈角度选择性**：0.2° 时 40，1.5° 时只有 3.5，差 10 倍以上；45° 入射角时只剩 4。
  2. **白色背景比彩色背景更亮**（60 vs 40），所以号牌上的白色区域（蓝牌的白字、白底牌的白底等）在夜间更易过曝。

**逆反射系数的定义：**

- `R_A`（coefficient of retroreflection）单位 `cd/(lx·m²)`；对于面积 A 的平面，逆反射发光强度 `I = R_A · E · A`，所以亮度 `L = I/A = R_A · E`（在给定几何下）。
- 也就是说，`R_A=40`、车牌处照度 `E=10 lx` 时，号牌亮色区域亮度约 400 cd/m²。
- 对比漫反射白漆（ρ≈0.8）：`L = ρ·E/π = 0.8×10/3.1416 ≈ 2.55 cd/m²`；**同照度下比值约 157 倍（≈7.3 EV）**。
- 对比沥青（ρ≈0.05–0.1）：`L≈0.16–0.32 cd/m²`；**比值约 1250–2500 倍（≈10.3–11.3 EV）**。
- 上述 ρ 值来自 BASF 的建筑材料太阳反射率表：新沥青 0.05、老化沥青 0.1、白色丙烯酸漆 0.8。[S6] `[有出处]`；`[推断]` 的只是把它们套到车牌/路面同照度假设。

**为什么夜间容易过曝：**

- 车灯（近光/远光）是近共轴光源：相机和车灯都在本车上，车牌逆反射把光“原路送回”相机方向；而车身/路面是漫反射，只有很小比例进入镜头。
- 白天太阳不在相机方向，逆反射不朝向相机；车牌亮度与普通白漆接近。所以同一套 AE 在白天正常，夜里车牌会亮很多。
- 专用 ALPR 更极端：红外光源与镜头共轴，逆反射直接回到传感器；专利 US9937879 就是“红外光源 + 逆反射标签 + 红外相机”的方案。[P3]
- 专利 US8750564 给出了同一现象的工程描述：光源与相机共置时，逆反射车牌“比车身亮很多”；如果按车身曝光，车牌过曝/饱和不可读；如果按车牌曝光，车身欠曝。他们的示例中逆反射亮度比漫反射高 **>35 倍**，并采用“相邻帧不同积分时间（车牌短曝光、车身长曝光）”来兼顾。[P1] `[有出处]`

**但要注意 Dashcam 的几何不是理想共轴：**

- 手机/记录仪相机通常在后视镜附近，车灯在下方 0.5–0.8 m、左右 0.7–1.5 m；对 10 m 外的车牌，观测角可能在 3–6°，而不是 0.2°。
- 按 GA 666 表，1.5° 时 `R_A` 只有 3.5；3–6° 可能更低（表外推），此时车牌相对白漆的倍率可能只有 2–6 倍，而不是 150 倍。
- 但车牌仍是白色、被车灯直接照射，且可能处于近光灯热区；实际夜间画面中车牌仍常比路面亮数倍到数十倍。**具体倍率必须用 task-7 的实拍 ROI 统计或实车标定得到，不能直接套 157×。**
- 另外，前车/对向车的车牌不一定被本车车灯正对；对向车的前牌主要由本车灯照亮，但对方车灯会直射镜头造成眩光，两个效应叠加。

**几何对倍率的影响（工作表）：**

| 观测角/入射角（近似） | R_A（蓝/绿/黄） | 相对白漆 ρ=0.8 | 相对沥青 ρ=0.1 | EV 差（相对白漆） |
|---|---:|---:|---:|---:|
| 0.2° / 5° | 40 | 157× | 1257× | +7.3 EV |
| 0.33° / 5° | 30 | 118× | 942× | +6.9 EV |
| 0.2° / 30° | 18 | 71× | 565× | +6.1 EV |
| 0.33° / 30° | 10 | 39× | 314× | +5.3 EV |
| 0.2° / 45° | 4 | 15.7× | 126× | +4.0 EV |
| 1.5° / 5° | 3.5 | 13.7× | 110× | +3.8 EV |

| 1.5° / 45° | 0.5 | 2.0× | 15.7× | +1.0 EV |

> 计算方法：`L_plate = R_A·E`；`L_diffuse = ρ·E/π`；比值 = `R_A·π/ρ`。表外角度不可直接外推，仅作数量级参考。

**结论：** 逆反射是夜间车牌过曝的物理原因；标准表给出 0.2° 下 40–60 cd/(lx·m²) 的强逆反射，理论上可比白漆亮 ~150 倍（7 EV）、比沥青亮 ~1000 倍（10 EV）；但 Dashcam 几何通常不是共轴，实际倍率会降到数倍到数十倍，必须实测。**控制策略应假设“车牌可能比路面亮 2–10 EV”，而不是固定 157×。**

### 3.2 车灯眩光、鬼影与曝光锁定

**眩光/鬼影的来源 `[有出处/推断]`：**

- 对向车灯/前车尾灯直射镜头：强光在镜头/IR-cut/保护玻璃多层界面产生**veiling glare（面纱眩光）**，抬高整幅黑电平，降低车牌局部对比度。McCann & Rizzi 的工作指出 veiling glare 是 HDR 采集的物理极限之一，多曝光只能改善量化，不能消除眩光限制。[X1]
- 挡风玻璃上的灰尘、油膜、雨滴、贴膜：产生散射和鬼影，夜间尤其明显；70mai 的产品页也把“windshield tint and reflections compensation”作为卖点。[V3]
- 镜头鬼影（ghosting）/光斑：强光源在镜片间多次反射，形成光斑/重影；车牌如果落在光斑里，局部对比度下降。
- 这些是**光学/散射**问题，AE 无法完全解决；缩短曝光可以降低眩光能量，但也会让路面更黑。CPL/遮光罩/清洁挡风玻璃是硬件侧缓解。

**曝光锁定（AE lock）为什么不是答案：**

- `CONTROL_AE_LOCK` 会锁定当前曝光参数，不再随场景变化；对动态行车场景，锁定后一旦进隧道/遇车灯就会过曝或欠曝。
- 官方文档给了“自动→手动”切换时用 AE lock 避免闪烁的流程（先 lock、等结果、抄曝光值、再关 AE），但这是**切换瞬间**用途，不是持续锁定。[A8]
- 因此：不要用 AE lock 跑全程；只在模式切换时短暂使用。

**夜间车灯场景的两种失败模式 `[有出处]` [P1]：**

1. **测光被车灯主导**：AE 看到大面积高光，降低曝光 → 车牌和路面都暗，车牌字符丢失。
2. **测光被暗路面主导**：AE 抬高曝光 → 号牌亮色区域饱和、字符晕开，车牌不可读。

**结论：** 眩光/鬼影会降低车牌对比度，AE 无法根治；曝光锁定不适合动态行车。**必须靠 ROI 高光保护 + 短曝光 + 光学/清洁/CPL 等物理手段组合。**

### 3.3 运动模糊：公式、表、经验值

**基本公式 `[推断]`（与专利的“角速度查找表”一致 [P7][P8]）：**

- 角速度：`ω ≈ v_lat / d`（rad/s），其中 `v_lat` 是车牌相对相机的横向速度，`d` 是距离。
- 像面模糊：`b_px = f_px · ω · t_exp = f_px · v_lat · t_exp / d`。
- 相对模糊（模糊占车牌宽度的比例）：`b_rel = (v_lat · t_exp) / W_plate`，其中 `W_plate=0.44 m`（44 cm 牌）。**注意：`f_px` 和 `d` 约掉了，所以变焦/靠近不会降低相对模糊；只有缩短曝光或降低相对横向速度。**
- 头对头接近（纵向运动）主要是径向膨胀：车牌宽度从 `w` 变为 `w·(1+v_long·t/d)`，边缘相对膨胀约 `v_long·t/d`（每边约一半）。10 m、60 km/h、1/100 s → 约 1.7% 宽度膨胀（63 px 牌约 1.1 px）。
- 滚动快门：CMOS 逐行读出，横向运动会产生倾斜/剪切；P30 读出时间未公开 `[待验证]`。短曝光能减少每行内模糊，但不能消除行间时间差。

**P30 车牌像素宽度估算 `[推断]`（27 mm 等效、全宽 1080p/4K）：**

| 距离 | 1080p 1× | 1080p 2× 变焦 | 1080p 2.1× 长焦 | 4K 1× |
|---:|---:|---:|---:|---:|
| 5 m | 127 px | 253 px | 266 px | 253 px |
| 10 m | 63 px | 127 px | 133 px | 127 px |
| 15 m | 42 px | 84 px | 89 px | 84 px |
| 20 m | 32 px | 63 px | 67 px | 63 px |
| 30 m | 21 px | 42 px | 44 px | 42 px |

> 公式：`w_px = f_px · 0.44 / d`，`f_px=1440`（1080p 全宽、27 mm 等效）；4K/2× 为 2880；2.1× 长焦为 3024。实际 FOV、裁切、镜头切换会改变数值，需实机标定。新能源牌 480 mm 约 +9%。

**车牌像素门槛：**

- GA/T 833（机动车号牌图像自动识别技术规范）：用于自动识别的图像中，车牌水平像素点应 **>100 px**。[S2]
- Milestone/Mobotix LPR 手册：最佳 LPR 至少 **2.7 px/笔画**；最小车牌宽度 130 px（30.5 cm 美国牌，停止/无隔行）、215 px（运动/隔行）、170 px（52 cm 欧洲牌，停止）、280 px（运动/隔行）；文字与背景像素值差至少 15。[S3][S4]
- 对中国 44 cm 牌，按 2.7 px/笔画和常见 10 mm 笔画估算约 120 px；GA/T 833 的 100 px 是下限，工程建议 **120–150 px** 才稳，低于 100 px 基本不可读。[推断]
- 这解释了为什么 P30 1080p 在 10 m 只有 63 px，**即使曝光完美也不满足自动识别门槛**；必须靠 2×/长焦或更近/更高分辨率。

**运动模糊表（1080p 1×，d=10 m，`b_px = 144·v_lat·t`）：**

| 曝光 \ 横向速度 | 2 m/s (7 km/h) | 5 m/s (18 km/h) | 10 m/s (36 km/h) | 15 m/s (54 km/h) |
|---|---:|---:|---:|---:|
| 1/30 (33.3 ms) | 9.6 px | 24.0 px | 48.0 px | 72.0 px |
| 1/60 (16.7 ms) | 4.8 px | 12.0 px | 24.0 px | 36.0 px |
| 1/100 (10 ms) | 2.9 px | 7.2 px | 14.4 px | 21.6 px |
| 1/250 (4 ms) | 1.2 px | 2.9 px | 5.8 px | 8.6 px |
| 1/500 (2 ms) | 0.6 px | 1.4 px | 2.9 px | 4.3 px |
| 1/1000 (1 ms) | 0.3 px | 0.7 px | 1.4 px | 2.2 px |

> 4K/2× 变焦时横向像素模糊也 ×2（因为 `f_px` ×2），但车牌宽度也 ×2，**相对模糊不变**。2.1× 长焦同理。

**相对模糊表（占车牌宽度 %，与距离/变焦无关）：**

| 曝光 \ 横向速度 | 2 m/s | 5 m/s | 10 m/s | 15 m/s |
|---|---:|---:|---:|---:|
| 1/30 | 15.2% | 37.9% | 75.8% | 113.6% |
| 1/60 | 7.6% | 18.9% | 37.9% | 56.8% |
| 1/100 | 4.5% | 11.4% | 22.7% | 34.1% |
| 1/250 | 1.8% | 4.5% | 9.1% | 13.6% |
| 1/500 | 0.9% | 2.3% | 4.5% | 6.8% |
| 1/1000 | 0.5% | 1.1% | 2.3% | 3.4% |

**经验值（可作为初始策略，最终以实车 OCR 标定为准）：**

- 头对头接近，10 m 以上、车速 ≤60 km/h：1/100–1/250 通常可接受（径向膨胀 1–2%）。
- 头对头接近，5 m 以内或相对速度 >60 km/h：1/250–1/500。
- 横穿/转弯/被超车（横向相对速度大）：1/500–1/1000；若一定要 OCR，宁可用高 ISO/稍暗画面，也不要长曝光。
- 静止/停车：1/30–1/50 优先亮度，但任何运动目标都可能糊。
- **不要指望 60 fps 解决模糊**：帧率只增加采样机会，不缩短每帧曝光；社区实测也指出 30 vs 60 fps 对车牌模糊没有保证。[V17]（社区经验，非严格实验）

**结论：** 运动模糊由曝光时间和相对横向速度决定；P30 1080p 在 10 m 处车牌仅 ~63 px，低于识别门槛，变焦提高像素但不降低相对模糊。**车牌优先模式应优先保证像素门槛（2×/长焦），再按场景选择 1/100–1/500 的快门，并在 50 Hz 约束下量化。**

### 4.1 方案总表

|---|---|---|---|---|

### 4.2 行车记录仪厂商的做法与局限

**VIOFO `[有出处]` [V1]：**

- 官方文章：HDR 通过“多次曝光（正常/过曝/欠曝）→ 合成”平衡亮暗；Sony STARVIS 的 **DOL HDR** 用于高对比场景；低光下合成多曝光让车牌更可读。
- 局限：DOL HDR 是“先拍亮图再拍暗图，再叠加”，两次拍摄有微小时间差；Sony 自己指出对快速运动目标会产生轮廓模糊/色差，Clear HDR（STARVIS 2/3）用单次拍摄同时得到亮暗图来消除运动伪影。[V7]
- 这说明：**多帧 HDR 对运动车牌有固有伪影**，不是万能；记录仪厂商也在向单帧 HDR 演进。

**70mai `[有出处]` [V2][V3]：**

- HDR 需要 CPU + 图像传感器支持；WDR 更偏软件/多曝光；两者目的都是兼顾亮暗。
- A900 产品页宣称 “adaptive auto exposure, selective image processing that highlights key details like license plates, and advanced compensation for windshield tint and reflections”。
- 局限：营销描述没有给出算法细节/可复现参数；不能作为第三方实现依据。

**Thinkware `[有出处]` [V4][V5]：**

- ARC 700：**Dual HDR 同时以两个不同快门速度拍两帧，再合成 30 fps HDR 视频**；产品页明确 HDR 仅在 Driving 模式（停车模式可能关闭）。
- 支持页：HDR 合并明暗曝光以减少车灯/路灯眩光、改善车牌可见性；部分型号开启 Super Night Vision 时会因处理带宽**自动关闭 HDR**。
- 这说明：HDR 与夜景增强/帧率/带宽存在取舍；不是所有场景都能同时开。

**BlackVue `[有出处]` [V6]：**

- ELITE 8：Dual HDR + Sony STARVIS 2；宣称 HDR 优化曝光，避免高光过亮和阴影过暗，提升车牌可读性。
- 局限：同样是厂商黑盒；依赖传感器/ISP。

**盯盯拍 DDPAI `[有出处]` [V18][V19]：**

- Z90 Max / Z60T 系列主打“三重 HDR”（前 4K + 后/车内 2K），配合 AI ISP、NightVIS 2.0；官方宣称可平衡车内/车外光线、提升夜间车牌识别。
- Z100 前摄 F1.0 大光圈，官方页面直接以“License Plate Capture / sharper license plate details in low-light”作为卖点。
- 局限：与其它厂商一样是黑盒；多路 HDR + 4K 对带宽/散热/帧率有代价；没有公开的曝光策略/阈值，不能直接移植到 Camera2 App。

**Sony/OmniVision/ON Semi（传感器侧）`[有出处]` [V7][V8][V9][V10]：**

- Sony：DOL HDR 有运动伪影；Clear HDR 单次拍摄解决；STARVIS 2/3 部分型号支持。
- OmniVision OX03H10：单次曝光 DCG + split pixel + LOFIC，140 dB，LFM，60 fps，面向车载 viewing。
- ON Semi：车规传感器 120–140 dB HDR + LED flicker mitigation（LFM）；LED 闪烁例子 100 Hz、10% duty、10 ms 周期。
- 结论：**传感器级 HDR/LFM 是解决隧道/LED/车灯场景的正道，但 P30 第三方拿不到。**

**华为 `[有出处/待验证]`：**

- 华为 Camera Kit 文档有“超级夜景”拍照流程（长曝光 + 图像回调），是静态拍照能力；不是实时视频 AE。[V16]
- P30 的 `hdrMovieSupported` 等私有 tag 表明 OEM 相机可能有 HDR 视频路径，但第三方无法通过公开 API 使用 `[待验证]`。
- 华为相机 App 的 ISO 204800 是 OEM 算法/多帧/长曝光的结果，不等于第三方 Camera2 单帧手动 ISO 上限。[V11]

| “Cost-Effective Restoration of Motion-Blurred Vehicle License Plates”`[X4]` | 日夜/不同车速/天气下的运动模糊车牌复原，提升 ALPR | 后处理去模糊可作为补刀，但不能恢复过曝 |
| libcamera AGC patch `[X5]` | 固定 ~10% 步长 + ±4% 死区的 bang-bang 控制器会过冲/振荡；改用比例控制 | 我们的控制环要避免“固定大步长 + 小死区”；用比例/阻尼/滞回 |

**结论：** 业界与学术界的共识是：**单曝光 + 车牌 ROI 目标 + 高光保持 + 运动模糊约束** 是最适合我们约束的路线；HDR/WDR 更好但需要传感器/HAL 支持，P30 第三方拿不到；后处理只能补可读性，不能救饱和。

## 5. 建议的控制策略（问题 4）

### 5.1 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 测光帧（YUV ImageReader，建议 960×540 或 640×360，≥10 Hz） │
│    - 全局/路面统计（p50/p90/p99、裁剪率）                    │
│    - 车牌 ROI 候选（亮度+内部对比+颜色+长宽比+时序跟踪）       │
│    - 车灯/天空/高光斑块检测                                   │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 2. 场景状态机（DAY/DUSK/NIGHT/TUNNEL/GLARE/FAILSAFE）         │
│    - 亮度水平 + 跳变斜率 + 车灯斑块 + GPS/时间                │
│    - 滞回/停留时间，避免抖动                                   │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. 曝光控制器（手动 AE_MODE_OFF）                             │
│    - 约束：车牌高光（p99/裁剪率）+ 运动模糊（快门上限）        │
│    - 目标：车牌 ROI 亮度达标 + 路面不低于地板                  │
│    - 执行：曝光时间优先，ISO 补足；50Hz 量化；阻尼/死区        │
└──────────────────────────┬──────────────────────────────────┘
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 4. 兜底：自动 AE（EV 负偏置）/ 固定安全曝光 / 降分辨率 / 告警   │
└─────────────────────────────────────────────────────────────┘
```

**核心原则：**

1. **车牌优先不是“全画面压暗”**：优先保护车牌亮色区域不饱和，同时给路面一个最低可见度地板；两者冲突时，车牌优先，但记录“路面过暗”事件。
2. **曝光时间优先于 ISO**：曝光时间同时影响高光、运动模糊、噪声；ISO 只影响亮度/噪声。过曝时先缩短曝光（在运动允许范围内），欠曝时先加曝光到运动上限、再加 ISO。
3. **系统 AE 只做兜底**：手动闭环失效、场景切换、HAL 异常时回自动 AE + EV 负偏置；不要用 AE regions 作为主执行器。
4. **单曝光**：P30 没有可用的 HDR/多帧路径；不要试图在 30 fps 单流里交替曝光（会闪烁）。
5. **可观测**：每次调整记录 `scene / ROI / 统计量 / 请求值 / 回读值 / 实际 fps`，否则无法调参。

### 5.2 场景分类与切换

**输入特征（建议）：**

- 路面 ROI：p50、p90、p99、裁剪率（>245）、时间 EMA/斜率。
- 车牌 ROI：是否存在、置信度、面积、p50/p90/p99、裁剪率、对比度、长宽比、颜色（蓝/黄/绿/白）。
- 高光斑块：车灯/路灯/天空的亮斑数量/面积/位置；是否在对向车道/画面中心。
- 全局：画面均值、上/下半亮度差、水平线/边缘密度（隧道口）。
- 外部：GPS 速度、时间、环境光传感器（手机有）、最近是否进过隧道/地下车库（可选地图）。
- 历史：上一状态、持续时间、最近一次大跳变。

**状态与阈值（初始建议，需实车调）：**

| 状态 | 进入条件（建议） | 主要策略 | 退出/切换 |
|---|---|---|---|
| DAY | 路面 p50 ≥85，无持续车灯斑块 | 系统 AE 或手动短曝光（1/500–1/1000）；EV 0；ISO 低 | 环境变暗持续 1 s → DUSK |
| DUSK | 路面 p50 40–85 | 手动/自动混合；车牌 ROI 加权；50 Hz 量化；ISO 中 | 更暗 1 s → NIGHT；变亮 2 s → DAY |
| NIGHT | 路面 p50 <40，或车灯斑块明显 + 低环境 | 手动；车牌 ROI 优先；快门 1/100 基准，按运动缩短；ISO 200–6400；50 Hz 量化 | 变亮持续 2 s → DUSK/DAY |
| TUNNEL | 路面亮度在 <300 ms 内下降 >25–30 且持续 >500 ms；或 GPS/地图进入隧道 | 快速提升曝光（允许 1–2 EV/步）；保护高光；保持 50 Hz 量化；出隧道前预降 | 亮度恢复并稳定 >1 s → DAY/NIGHT |
| GLARE | 对向车灯斑块面积 >1–2% + 全局 p99 高 + 车牌对比下降 | 短曝光/负 EV/车牌 ROI 优先；必要时降低目标；提示“眩光” | 斑块消失 0.5 s → 上一状态 |
| FAILSAFE | 测光流丢失、HAL 错误、回读偏差大、fps 低 | 自动 AE + EV −0.5（夜）/0（日）；固定 1/100 ISO 1600 兜底；告警 | 恢复后延时回主策略 |

**滞回建议：**

- 进入 NIGHT：连续 10–15 帧（0.3–0.5 s）满足；退出：连续 50–60 帧（~2 s）。
- 进入 TUNNEL：2–3 帧（<100 ms）触发；退出：亮度稳定 1 s 后。
- GLARE：3 帧触发；消失 0.5 s 退出。
- 所有阈值用“进入/退出不同值”（如进入 <40、退出 >60），避免在边界抖动。
- 场景变化时重置控制器 seed 或进入 transition 模式（允许更大步长，但仍受高光/运动约束）。

**P30 特别说明：**

- 不能依赖 `CONTROL_AE_STATE` 做场景分类（AE OFF 时它是 INACTIVE）；只能用自己的统计。
- 不能依赖 `STATISTICS_SCENE_FLICKER` 一定存在（Optional，FULL 才有保证）；若为 null，在中国默认按 50 Hz 保守处理，或通过时间序列检测 100 Hz 亮度波动。
- 隧道检测不能只看“变暗”：进地下车库、桥下、树荫也会变暗；用持续时间 + 边缘/结构 + GPS/地图（可选）综合。

### 5.3 测光 ROI 选取

**ROI 结构（建议）：**

| ROI | 范围/权重 | 用途 | 备注 |
|---|---|---|---|
| 车牌 ROI | 检测框外扩 1.5–2×；权重 0.55–0.7 | 车牌 p50/p90/p99/裁剪率；高光保护主依据 | 需要检测/跟踪；无检测时不用 |
| 路面 ROI | 画面下方 15–85% x、40–92% y；权重 0.25–0.35 | 保证路面可见、场景分类 | 当前 320×240 模式用的中心带可作退化方案 |
| 全局 ROI | 全画面，权重 0.1–0.15 | 防 ROI 误检导致整体跑飞 | 只用于兜底/交叉校验 |
| 排除区 | 顶部 0–25%（天空）、车灯/路灯亮斑、画面边缘 | 不参与高光保护/目标统计 | 车灯是“光源”不是“目标” |

**车牌 ROI 检测（在 960×540 或 640×360 上）：**

- 亮色矩形：p90 高、内部有暗字符（p90−p50 大）、长宽比约 2.5–4.5、面积在合理范围、位于下方 38–93% 区域。
- 颜色：中国蓝牌（B 高、R/G 低）、黄牌（R/G 高、B 低）、绿牌（G 高）、白牌（RGB 均衡）；颜色可显著降低误检（当前草案只用 Y，建议加 U/V）。
- 时序：连续 2–3 帧 IoU 稳定才认为有效；用简单 tracker/Kalman；丢失 >0.5 s 清除。
- 多候选：选置信度最高/面积最大/最靠近画面中心下方的一个；不要把多个远处亮块合并成一个 ROI。
- 误检来源：白色路面标线、广告牌、车灯、反光路牌、隧道灯、前车银色保险杠；用长宽比/颜色/内部字符结构/时序排除。
- 分辨率：960×540 下 10 m 车牌约 31 px 宽（1080p 63 px 的一半），字符结构可能不足；**建议车牌优先模式默认 2× 变焦或 2.1× 长焦**，或把测光流提高到 1280×720（带宽/帧率需实测）。640×360 下 10 m 约 42 px（1×）/84 px（2×），更可行。

**与 `CONTROL_AE_REGIONS` 的关系：**

- 手动模式下 AE regions 不参与（没有 AE 例程）；不要浪费时间。
- 自动兜底模式下，可以把车牌 ROI 映射成 region（weight=1000）作为提示；但必须验证 HAL 是否响应，且坐标要按 `SCALER_CROP_REGION` 映射到 active array。
- API 29 没有 `CONTROL_ZOOM_RATIO`，用 `SCALER_CROP_REGION` 时 ROI 坐标 = crop.left + ROI_x × crop.width / meter_width；别直接拿 metering 坐标当 active array。

### 5.4 控制律：曝光 vs ISO，先保高光还是先保亮度

**推荐的控制优先级（从高到低）：**

1. **车牌高光不饱和**：车牌 ROI 的 p99 ≤ 245、裁剪率（>245）≤2%；若超过，先缩短曝光。
2. **车牌亮度达标**：车牌 ROI 的 p50/p90 落在目标区间（见 5.5），否则增加曝光/ISO。
3. **运动模糊可接受**：曝光时间不超过由相对横向速度/车速估计的上限。
4. **路面可见**：路面 p50 不低于地板（如 35–50），否则加 ISO/曝光。
5. **噪声/画质**：在满足以上前提下尽量低 ISO；超过 `SENSOR_MAX_ANALOG_SENSITIVITY` 后谨慎加 ISO。

**为什么“过曝先缩曝光”而不是“先降 ISO”：**

- ISO/gain 通常在传感器读出之后施加；如果像素/ADC 已经饱和（full well/满量程），降低 ISO 不能恢复被截断的高光，只是把已饱和的值乘小。
- 缩短曝光直接减少到达传感器的光量，是真正的高光保护；同时还能减少运动模糊。
- 只有在“未饱和但 ISP/后级增益导致裁剪”的情况下，降 ISO 才有效；这需要实测（同一曝光下改 ISO，看号牌亮色区域是否从 255 降下来）。
- 因此：**默认曝光优先；降 ISO 作为第二手段/实验项**。当前草案的“先降 ISO、ISO 到底再缩快门”需要实验证伪或限定场景。

**控制量选择：**

- **白天**：优先系统 AE（它擅长中灰场景）；若逆光/车牌欠曝，用 ROI 加权/EV +0.3~+0.7；避免为了车牌把天空压成死白/黑。
- **黄昏/夜间**：手动；曝光时间按运动上限，ISO 补足；车牌 ROI 优先。
- **隧道**：入口快速加曝光（允许 1–2 EV/步），出口快速减曝光；保持高光保护；用前馈（亮度斜率/GPS）而不是等变暗。
- **极暗无路灯**：车牌由本车灯照亮，逆反射/白色使车牌相对亮；可以承受较短曝光（1/250–1/500）和较高 ISO；路面会很暗，接受或后期提亮。
- **有路灯/LED**：50 Hz 量化 + 高光保护；LED PWM 可能造成 banding/闪烁，需时间中值/滞回。

**伪代码（建议实现，不是现有代码）：**

```
每 100–150 ms 处理一帧测光：
  stats = measure(roadROI, plateROI, globalROI)
  scene = updateScene(stats)
  if (!plateValid) {
     // 无车牌：路面优先，避免越压越黑
     target = roadTarget(scene)
     err = log2(target / max(roadP90, 1))
     if (roadClip > 12%) err = min(err, -0.6)
     else if (roadClip > 5%) err = min(err, -0.2)
     if (scene == NIGHT) err = max(err, -0.45)
  } else {
     target = plateTarget(scene)
     err = log2(target / max(plateP90, 1))
     if (plateClip > 2%) err = min(err, -0.8)   // 高光优先
     else if (plateClip > 0.5%) err = min(err, -0.25)
     if (plateP90 < plateMin(scene) && plateClip < 0.1%) err = max(err, +0.35)
  }
  if (abs(err) < 0.10) return;                  // 死区
  err = clamp(err, -maxStep, +maxStep) * gain;  // 比例 + 限幅
  maxShutter = min(frameNs, motionCap(scene, speed, plateTrack))
  minShutter = (flicker50Hz ? 10ms : 0.5ms)     // 50Hz 量化见 5.6
  if (err > 0) {                                // 欠曝
     wantExp = exp * 2^err
     newExp = quantize(wantExp, minShutter, maxShutter)
     residual = wantExp / newExp
     newIso = iso * clamp(residual, 1.0, 2.0)
  } else {                                      // 过曝
     // 先缩曝光；只有曝光到 min 才降 ISO
     wantExp = exp * 2^err
     newExp = quantize(wantExp, minShutter, maxShutter)
     if (newExp > minShutter) {
        newIso = iso                      // 曝光已减少，先不动 ISO
     } else {
        newIso = iso * 2^err              // 曝光到底，再降 ISO
     }
  }
  clamp ISO 到 [isoFloor, isoCap]
  如果连续 2 帧同向误差，正常；如果方向翻转，减半步长/保持 2 帧（阻尼）
  应用 setRepeatingRequest；记录请求值；从 CaptureResult 回读实际值，偏差大则修正/兜底
```

### 5.5 目标亮度与参数（初始建议，待 task-7 标定）

**图像统计口径：**

- 所有值按 8-bit luma；如果实际是 limited range（16–235），先线性拉伸到 0–255，或改用归一化 0–1。
- 车牌 ROI 用 p50/p90/p99 + 裁剪率，不要只用均值（均值会被黑字符拉低）。
- 裁剪阈值建议 245/250；当前代码用 238/246，需与实际 YUV/编码范围对齐。

**建议目标区间（初始）：**

| 场景 | 车牌 p50 | 车牌 p90 | 车牌 p99 | 车牌裁剪率 | 路面 p50 地板 | ISO 上限 | 快门基准 |
|---|---:|---:|---:|---:|---:|---:|---|
| DAY | 120–180 | 180–220 | ≤245 | ≤1% | 80–140 | 400–800 | 1/500–1/2000（AE 决定） |
| DUSK | 100–170 | 170–215 | ≤245 | ≤2% | 50–100 | 1600 | 1/125–1/500 |
| NIGHT | 80–160 | 160–210 | ≤245 | ≤2% | 25–60 | 6400 | 1/100 基准，按运动 1/250–1/1000 |
| TUNNEL | 100–180 | 180–220 | ≤245 | ≤3%（瞬态） | 40–90 | 3200 | 1/50–1/250 |
| GLARE | 70–150 | 150–200 | ≤245 | ≤3% | 20–50 | 6400 | 1/250–1/1000 |
| 静止/停车 | 100–180 | 180–220 | ≤245 | ≤1% | 30–80 | 3200 | 1/30–1/100 |

> 这些是“起点”，不是标准。最终应以“车牌 OCR 成功率 + 人眼可读 + 路面可见”的实车数据回归；task-7 的取证结果会给出更可靠的背景亮度/过曝比例/对比度阈值。

**对比度/锐度：**

- 字符与亮色背景对比：`p90 − p10` 至少 60（8-bit）作为可读性代理；低于 40 基本难 OCR。
- 边缘锐度：可用 Laplacian 方差/梯度均值，但受编码/降噪影响；建议用“OCR 置信度/字符分割成功率”作为最终指标。
- 过曝像素比例：亮色区域允许少量裁剪（≤2%），但字符区域不能整块 255；否则字符消失。

**P30 参数建议：**

- 分辨率：默认 1080p（稳定）；车牌优先时开 2× 数字变焦或切 2.1× 长焦；2.7K/2K 宽屏若 HAL 稳定可试，但 4K 不作为生产默认（README 已记录不稳定）。
- 帧率：30 fps（25/24 可作更亮备选，但 25 fps 下 40 ms 曝光是 50 Hz 安全档；24 fps 的 41.7 ms 不安全）。
- 码率：1080p 建议 ≥16–24 Mbps；车牌细节在压缩下会掉，尤其是夜间高 ISO 噪声；不要为了省空间把码率压到 8–12 Mbps。
- ISO 上限：默认 6400；若实测 6400 噪声导致 OCR 崩，降到 3200 并接受更暗；如果 HAL 允许更高且噪声可控，可在极暗场景试验。
- 快门基准：夜间 1/100；头对头 10 m+ 可 1/100–1/250；近距离/横穿 1/250–1/1000；白天 1/500–1/2000（由 AE/亮度决定）。

### 5.6 50 Hz 防闪烁（中国场景的硬约束）

**事实 `[有出处]` [A6][A22][S9]：**

- 50 Hz 交流电 → 灯光亮度以 100 Hz 波动；曝光时间取 1/100 s 的整数倍可避免 banding。
- 手动模式下 `CONTROL_AE_ANTIBANDING_MODE` 不生效；必须应用自己保证。
- `STATISTICS_SCENE_FLICKER` 可报告 NONE/50HZ/60HZ，但它是 Optional（FULL 才有保证），P30 可能为 null `[待验证]`。
- 中国专利 CN102025919B 也明确：中国供电 50 Hz，默认曝光时间取 1/100 的整数倍；美国 60 Hz 则取 1/120 的整数倍。[S9]

**30 fps 下可用档位：**

| 帧率 | 帧间隔 | 50 Hz 安全曝光（≤帧间隔） | 不安全（常见错误） |
|---|---:|---|---|
| 30 fps | 33.33 ms | **10 ms (1/100)、20 ms (1/50)**；30 ms (1/33.3) 理论安全但只剩 3.3 ms 开销，需实测是否掉帧 | 16.7 ms (1/60)、33.3 ms (1/30)、8 ms (1/125)、4 ms (1/250) |
| 25 fps | 40 ms | **10 ms、20 ms、40 ms (1/25)** | 16.7、33.3、8、4 ms |
| 24 fps | 41.67 ms | **10 ms、20 ms、40 ms** | 16.7、33.3、41.7、8、4 ms |
| 60 fps | 16.67 ms | **10 ms** | 16.7 ms 及以上（超帧预算） |

> 如果场景无 50 Hz 照明（纯车灯、乡村黑夜），可以使用 4/2/1 ms 短曝光；一旦检测到 50 Hz 或不能确定，保守量化到 10 ms 整数倍。

**检测/决策建议：**

- 优先读 `STATISTICS_SCENE_FLICKER`；若为 50HZ → 强制量化；若 NONE → 允许短曝光；若 null → 按时间/地点默认（中国默认 50 Hz）。
- 可选自测：连续帧的路面均值做 FFT/方差，检测 100 Hz 亮度波动；成本低，但容易被运动干扰。
- 冲突处理：如果“需要 1/500 防模糊”与“50 Hz 需要 10 ms”冲突，按场景选：
  - 城市路灯/LED 多 → 优先 10 ms，接受一定模糊；
  - 乡村/车灯自照明 → 优先 1/500，接受可能的 banding；
  - 隧道内荧光灯/LED → 优先 10 ms。
- 记录每次使用的档位与 `sceneFlicker`，便于复盘。

**结论：** 当前草案的快门表包含 1/60、1/30、1/125、1/250，均不是 50 Hz 安全档；注释“兼顾 50Hz”不成立。**应改为“10/20/30 ms 安全档 + 无闪烁时可选短曝光”，并加入 `STATISTICS_SCENE_FLICKER`/时间检测。**

### 5.7 收敛、滞回、抗振荡

**问题 `[有出处]` [X5]：**

- libcamera 的 AGC 补丁指出：固定 ~10% 步长 + ±4% 死区的 bang-bang 控制器，在正确曝光落在一步之内时会过冲，产生可见亮度振荡；改用比例控制后改善。
- 我们的场景更难：车牌 ROI 小、统计噪声大、HAL 有延迟、车灯/路灯会突变；固定大步长 + 小死区很容易“拉风箱”。

**建议：**

- **死区**：±0.10–0.15 EV（约 ±7–10% 亮度）；小于死区不动作。
- **步长**：正常 0.2–0.4 EV/次；场景切换/隧道 0.8–1.2 EV/次；不要 1.6 EV/次连续打（当前草案 transition 1.6 EV 偏大）。
- **比例增益**：`step = clamp(k·err, -maxStep, +maxStep)`，`k≈0.5–0.8`；大误差时饱和，小误差时线性。
- **方向翻转阻尼**：连续 2 次误差反向 → 步长减半/冻结 2 帧；当前草案的 `flipCount` 思路正确。
- **ROI 平滑**：车牌 ROI 统计用 3–5 帧中值/EMA；ROI 丢失/跳变时不要立即大改曝光。
- **高光保护进入快、退出慢**：检测到裁剪 2 帧内降曝光；裁剪消失后至少保持 10–15 帧再缓慢放宽 ceiling（当前模式 1 的 1.02/frame 释放可参考）。
- **场景切换**：进入 NIGHT/TUNNEL 允许较大步长；退出/恢复时用较小步长，避免“闪一下”。
- **控制周期**：建议 100–150 ms（6.7–10 Hz）；如果用 960×540 测光，可尝试 10–15 Hz，但要做 CPU/帧率预算。
- **回读校验**：每次 `setRepeatingRequest` 后，从 `CaptureResult` 读实际 exposure/ISO；如果连续 5 帧与请求偏差 >20%，说明 HAL 不接受/夹取，改用回读值做闭环或降级。
- **AE 状态**：手动模式 `CONTROL_AE_STATE=INACTIVE`，不能用它判断收敛；用自己的统计 + 帧计数。

**收敛目标（建议验收）：**

- 隧道入口：亮度突变后 ≤0.5 s 内回到目标 ±1 EV；无 >300 ms 的全黑/全白。
- 夜间车灯进出：≤1 s 稳定；无可见的 2 Hz 以上亮度振荡。
- 白天逆光：≤1 s 稳定；车牌不持续过曝 >2 s。

### 5.8 失效兜底

| 失效 | 检测 | 兜底动作 | 恢复 |
|---|---|---|---|
| 测光流创建失败/停止 | `meteringReader==null`；>500 ms 无帧 | 切自动 AE + EV −0.5（夜）/0（日）；或固定 1/100 ISO 1600 | 测光恢复后 1 s 回主策略 |
| 车牌检测失效/误检 | ROI 连续丢失/跳变；统计异常 | 退回路面 ROI + 全局；不启用高光保护 | ROI 稳定 1 s 后恢复 |
| HAL 不响应曝光/ISO | 回读与请求偏差 >20% 连续 5 帧 | 用回读值闭环；仍不行则自动 AE | 回读正常后恢复 |
| HAL 错误/断流 | `onError`/`ERROR_CAMERA_DEVICE` | 现有重连逻辑；降分辨率/帧率；记录 EventLog | 重连成功 |
| 帧率下降/掉帧 | 实际 fps <25 或编码丢帧 | 停止改曝光；降测光频率/分辨率；必要时回自动 AE | fps 恢复 |
| 过热 | 设备温度/编码器报错 | 降分辨率/码率；减少测光频率；提示用户 | 温度下降 |
| 画面过暗（兜底失败） | 路面 p50 <20 持续 1 s | 强制提高 ISO/曝光到安全上限；仍不行则自动 AE | 亮度恢复 |
| 画面过曝（兜底失败） | 全局裁剪 >30% 持续 1 s | 强制降曝光/ISO；仍不行则自动 AE | 裁剪下降 |
| 模式切换闪烁 | 自动↔手动切换 | 按官方 AE lock 流程；切换后 2–3 帧不调整 | 稳定 |

**兜底原则：**

- 任何自动策略都必须有“回到安全自动模式”的路径；不能因为车牌 ROI 误检把画面锁死。
- 夜间兜底不能选“更暗”的自动 AE（会失去证据），应选 EV −0.5 左右的自动 AE 或固定 1/100 ISO 1600。
- 所有兜底动作写 EventLog（场景、原因、请求/回读），便于事后分析。

### 5.9 光学/分辨率/编码的配合

- **车牌像素优先**：1080p + 2× 数字变焦（或 2.1× 长焦）在 10 m 处约 127–133 px，刚过 120–130 px 门槛；比 1080p 1× 的 63 px 强一倍。代价是 FOV 减半/切换镜头；建议提供“车牌模式”开关，而不是默认全程 2×。
- **2.7K/2K 宽屏**：若 HAL 稳定，可提供 2560×1080/3648×2056 选项，提升车牌像素；但要注意码率、发热、帧率、4K 不稳定（README）。先用 1080p 做基线。
- **码率**：夜间高 ISO 噪声会吃掉码率；车牌细节需要足够码率。1080p 建议 16–24 Mbps；不要用 8 Mbps 跑夜间车牌优先。
- **锐化**：现有 App 有锐化等级；轻/中锐化可改善车牌边缘，但会放大噪声/光晕；建议车牌优先模式用轻度，且可配置。
- **后处理 LTM（可选）**：如果车牌优先导致路面太暗，可在 GL 预览/编码路径加入局部 tone mapping（提阴影、压高光），但：
  - 不能恢复已裁剪的高光；
  - 会放大噪声/产生光晕；
  - 需要 GPU 性能/延迟预算；
  - 证据合规上要保留原始参数/可复现性。
  建议作为 P2 试验，不要阻塞主路径。
- **专用取证帧（可选）**：在检测到车牌且当前曝光无法兼顾时，用一次静态抓拍（`TEMPLATE_STILL_CAPTURE`/JPEG 或高分辨率 YUV）以短曝光+高 ISO 取一张“车牌帧”，与视频流分开。Camera2 同一 session 加 JPEG target 可能影响帧率；需要实测。这比逐帧交替曝光更实用。

### 5.10 推荐参数一页纸（P30 初始版）

## 9. 结论（可执行建议）

### 9.1 技术路线结论

1. **主路线：单曝光 + 车牌 ROI 优先 + 高光保护的手动闭环 + 系统 AE 兜底。** 这是 P30 API 29 第三方在 30 fps 下唯一可控、可解释、可回退的路线。[A3][A17][P6][P9][D3]
2. **不要依赖 `CONTROL_AE_REGIONS` 和 EV 做夜间主方案。** regions 语义不保证高光优先、厂商实现差异大；EV 是全局偏置，无法兼顾车牌与路面。[A1][A2][A42]
3. **HDR/WDR/10-bit/RAW/reprocessing 不作为 P30 第三方主路径。** 公开 API 要么需要 API 33+，要么是静态拍照，要么只支持 preview/still；私有 tag 未证实、不可依赖。[A24][A25][A16][A18][A19]
4. **车牌像素是硬门槛：** 1080p 1× 在 10 m 只有 ~63 px，低于中国 100 px 下限和工程 120–150 px 建议；车牌优先模式应默认 2×/2.1× 长焦，或使用稳定的 2.7K；4K 不作为生产默认。[S2][S3][S4][D1]
5. **50 Hz 是硬约束：** 手动模式必须自己量化到 10 ms 整数倍（30 fps 下 10/20/30 ms）；1/60、1/30、1/125、1/250 不是安全档；用 `STATISTICS_SCENE_FLICKER`/时间检测决定是否可用短曝光。[A6][A22][S9]
6. **高光保护优先缩曝光，ISO 只做补亮度；** “先降 ISO 再缩快门”需要实验区分“传感器饱和”与“后级增益裁剪”，不能默认成立。[A3][A4][推断]
7. **运动模糊看相对横向速度，不看本车速度：** 头对头 10 m+ 可用 1/100–1/250；近距离/横穿用 1/500–1/1000；变焦只提高像素，不降低相对模糊。[P7][P8][推断]
8. **场景状态机 + 滞回/阻尼 + 失效兜底是稳定性的关键：** 夜间/隧道/眩光/白天逆光分开处理；进入快、退出慢；死区 0.1–0.15 EV、比例增益、翻转阻尼；测光流/HAL/帧率异常时自动回退。[X5][A23]

### 9.2 落地优先级（给实现/验证）

- **P0（先做）**
  1. 固化 1.3 节设备能力（尤其 AE step/range、max regions、ISO/曝光范围、960×540 流、vendor keys）。
  2. 把 50 Hz 量化改对（10/20/30 ms；删掉 1/60、1/30 作为安全档）。
  3. 确认高光保护顺序（曝光 vs ISO）用实验定。
  4. 车牌模式默认 2×/长焦；测光流至少 960×540（最好 1280×720 或 2× 后再测）。
  5. 加测光流失败/HAL 异常/回读偏差兜底。
  6. 用实车数据标定目标（车牌 p90/p99/clip、路面地板）。
- **P1（稳定/体验）**
  1. 场景状态机加车灯/眩光/隧道出口/斜率；GPS/地图可选。
  2. ROI 检测加颜色/长宽比/跟踪，降低误检。
  3. 滞回/阻尼参数扫描；长跑/热测试。
  4. AWB 锁定/监控；fps/回读监控。
  5. 2.7K/宽屏稳定性评估。
- **P2（可选）**
  1. 私有 tag 实验、LTM/去眩光、轻量车牌检测模型、滚动快门校正、静态取证帧。
  2. 任何实验都必须有回退和开关，不影响主路径。

### 9.3 不建议做的事（负面清单）

- 不要用 `CONTROL_AE_REGIONS` 作为夜间主执行器。
- 不要用 EV −2 硬压夜间车牌（路面会黑，且不同 HAL 响应不可预测）。
- 不要在 30 fps 单流里逐帧交替长短曝光（画面会闪烁；除非只用于离线/取证帧）。
- 不要用 RAW/reprocessing/10-bit 试图“拍完再救”车牌高光（数据已丢）。
- 不要把 Huawei 私有 tag 放进生产主路径（固件/机型依赖）。
- 不要用 1/60、1/30、1/125、1/250 作为 50 Hz 安全档。
- 不要只看本车速度决定快门（要估计相对横向运动）。
- 不要只追 p90 均值而不看 p99/裁剪率/字符对比。
- 不要用强锐化/生成式修复“造”车牌细节（证据合规风险）。

## 附录 A：关键公式与计算

### A.1 亮度、EV、ISO

- 曝光值（ISO 100）：`EV100 = log2(N²/t) - log2(ISO/100)`（N 光圈，t 秒）。
- 场景亮度（K=12.5）：`L = 2^(EV100 - 3)` cd/m²（近似）。
- 漫反射亮度：`L = ρ·E/π`。
- 逆反射车牌亮度：`L = R_A·E`（给定几何，R_A 单位 cd/(lx·m²)）。
- 同照度下比值：`ratio = R_A·π/ρ`；EV 差 = `log2(ratio)`。
- 例：R_A=40、ρ=0.8 → ratio≈157（7.3 EV）；R_A=40、ρ=0.1 → ratio≈1257（10.3 EV）；R_A=3.5、ρ=0.8 → ratio≈13.7（3.8 EV）。

### A.2 运动模糊

- 横向：`b_px = f_px·v_lat·t/d`；`b_rel = v_lat·t/0.44`（44 cm 牌）。
- 纵向（头对头）：宽度相对膨胀 ≈ `v_long·t/d`（每边约一半）。
- 像素焦距：`f_px = W / (2·tan(HFOV/2))`；P30 27 mm 等效、1080p 全宽 ≈ 1440 px。
- 车牌像素宽：`w_px = f_px·0.44/d`。

### A.3 亮度/曝光示例（仅数量级）

| 场景 | 假设 | 计算 | 结果 |
|---|---|---|---|
| 车牌（近共轴） | R_A=40, E=10 lx | L=400 cd/m² | EV100≈11.6 |
| 车牌（斜视） | R_A=3.5, E=10 lx | L=35 cd/m² | EV100≈8.6 |
| 白漆路面 | ρ=0.8, E=10 lx | L=2.55 cd/m² | EV100≈4.3 |
| 沥青路面 | ρ=0.1, E=10 lx | L=0.32 cd/m² | EV100≈1.4 |
| 车牌在 f/1.8, 1/500, ISO? | EV100=11.6 | ISO≈200 | 车牌正确曝光 |
| 沥青在 f/1.8, 1/500, ISO? | EV100=1.4 | ISO≈63,500 | 同一设置下路面极暗 |

> 这说明：在同一曝光下，车牌正确时路面可能暗 6–8 EV；车牌优先必然牺牲路面。实际倍率取决于几何/R_A，必须实测。
